# 编辑器高亮（Highlight）使用说明

> 适用范围：MarkCraft 编辑器 **WYSIWYG / 富文本模式**（格式工具栏）。
> 最近变更：主按钮改为「应用上次颜色」，色板由 5 色扩至 **16 色**，并**记住上次用过的颜色**。

---

## 1. 界面结构（split button）

工具栏上的高亮图标是一个**两段式按钮**（和 Word / VS Code 一致）：

```
┌──────────┬─┐
│  🖊 高亮  │▾│      ← 主按钮（点它 = 直接上色）
└──────────┴─┘
   └ 图标下方那条 3px 彩色小横条 = 当前「上次颜色」指示
     · 右侧 12px 小箭头 = 展开 16 色调色板
```

| 操作 | 结果 |
| --- | --- |
| 点**主按钮** | 对选区**直接应用「上次颜色」**；若选区已经是该颜色，则**取消高亮**（切换语义） |
| 点**右侧小箭头** | 展开 / 收起 **16 色调色板**（24 色块，两行 × 8） |
| 点**调色板里的色块** | 应用该颜色，**并把它记成「上次颜色」**，面板自动收起 |
| 再看主按钮下的小横条 | 就是下次点主按钮会用到的颜色 |

> 关键区别：**只有「在调色板里挑色」会改掉「上次颜色」**。点主按钮只是「用上次那支笔」。
> 所以选过一次红，之后连点主按钮就一直是红——不会每次都跳回黄。

## 2. 快捷键与其它入口

| 入口 | 行为 |
| --- | --- |
| `Ctrl + Shift + H`（macOS `Cmd + Shift + H`） | 与**主按钮完全相同**：应用 / 切换「上次颜色」 |
| 编辑器内**右键菜单 → 高亮** | 同上（应用 / 切换「上次颜色」） |

三条入口语义一致，都**不会**打开调色板；要换色一律走右侧小箭头。

## 3. 16 色一览（调色板顺序，两行 × 8）

| 行 | 颜色 |
| --- | --- |
| 第 1 行 | 黄(yellow) · 琥珀(amber) · 橙(orange) · 深橙(deep-orange) · 红(red) · 粉(pink) · 紫(purple) · 深紫(deep-purple) |
| 第 2 行 | 靛(indigo) · 蓝(blue) · 浅蓝(light-blue) · 青(cyan) · 蓝绿(teal) · 绿(green) · 浅绿(light-green) · 灰(gray) |

- **默认颜色**：黄（`yellow`）。从没挑过色之前，主按钮就是黄的。
- 正文里的颜色是**半透明**的（正文压在底色上仍然清晰）；调色板色块与主按钮指示条用的是**同色不透明版**，
  所以深色主题下也能分辨。
- 鼠标悬停到色块上会放大提示，色块的 `title` 就是色名（如 `deep-orange`）。

## 4. Markdown 存储格式（源码模式可见）

| 编辑器里 | 源码里 |
| --- | --- |
| 黄色高亮 | `==文字==` |
| 其它颜色高亮 | `==文字\|颜色名==`，例如 `==重点\|red==` |
| 深浅组合名 | `==重点\|deep-orange==`、`==重点\|light-blue==` |

- 黄色是默认色，回写时会**归一化成最短形态** `==文字==`（历史文档里 `==文字|yellow==` 与 `==文字==`
  两种写法都有，统一成短形态以免每次编辑都产生多余 diff）。
- 其它颜色原样带色名往返，**连字符色名不会被丢掉**。

## 5. 颜色记忆存在哪

- 存在本地设置里（`localStorage` 的 `markcraft_settings.lastHighlightColor`），**关闭再打开仍然记得**。
- 存量值若非法（手改过、或是旧版本已废弃的色名），一律**安全回退为黄**，不会出现「高亮不上色」。
- 想恢复默认：把颜色重新在调色板里选一次黄即可。

## 6. 常见问题

| 现象 | 说明 |
| --- | --- |
| 点了主按钮，颜色「被取消了」 | 这是切换语义：选区已经是该颜色时再点就是取消。想要别的颜色请用右侧小箭头挑。 |
| 主按钮的横条颜色不是我想的那个 | 点一次「右侧小箭头」去调色板挑色，挑完横条就会跟着变（这就是「记住上次颜色」）。 |
| 选中多段交叉格式的文本后高亮 | 只会给选区内的文本打高亮，其它格式（粗体/链接等）保持不变。 |
| 源码模式看不到颜色 | 源码里是 `==文字\|颜色名==` 这种写法，不是 HTML 标签。 |
