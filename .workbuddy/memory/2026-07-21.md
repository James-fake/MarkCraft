# 2026-07-21 修复：进入 canvas 白板报 "process is not defined"

## 现象
开发服务器（5173，smoke 配置）进入 canvas 白板功能时，界面报 Application Error：`process is not defined`。

## 根因
`@excalidraw/excalidraw` 的 CJS 入口 `main.js` 在浏览器端引用全局 `process.env.IS_PREACT` / `process.env.NODE_ENV`。应用内虽间接打包了一个 `process` 浏览器 polyfill，但它是**模块作用域**（未挂到 `window.process`），故 Excalidraw 引用的全局 `process` 不存在而报错。
- 确认：Excalidraw 全部 `process` 引用均为 `process.env.*`（main.js 的 IS_PREACT/NODE_ENV + dev bundle 的 NODE_ENV），无裸 `process` 调用。
- 注意：Vite 的 dep 优化缓存键不包含 `define`，改 define 不会让旧的优化产物（含 `process`）失效；且沙箱 safe-delete 守卫拦截对 `node_modules/.vite*` 的批量删除，无法强制重优化。

## 修复（两层）
1. **运行时 shim**：`index.html` `<head>` 在 module 前注入 `window.process = window.process || { env: { NODE_ENV: 'development', IS_PREACT: 'false' } }`。与 safe-delete 守卫无关，立即可用。
2. **构建期 define**：`vite.config.ts` 与 `vite.smoke.config.ts` 改为函数式 `defineConfig(({mode}) => ({ define: { 'process.env': JSON.stringify({ NODE_ENV: mode, IS_PREACT: 'false' }) } }))`（注意函数式需 `}))` 收尾，曾漏写导致配置加载失败，已修）。

## 验证
- dev server 5173 仍 200，served index.html 含 shim（grep 命中 1）。
- `vite build`（默认配置）→ exit 0；产物 `dist-prodcheck` 中 `process.env.*` 引用为 0（define 生效）；built index.html 含 shim。
- `src/` 仅 `engineNodeTest.ts`（Node 测试文件）用到 `process.exit`，不在浏览器包内，无影响。
- 残留：`dist-prodcheck/`、`build-verify/`（safe-delete 守卫无法清理，无害，勿提交）。

## 结论
进入白板不再抛 `process is not defined`；dev（shim兜底）+ 生产（define 替换）双保险。

# 2026-07-21 续：进入 canvas 白板报 "Maximum update depth exceeded"

## 现象
修复 process 后进入白板，报 Application Error：`Maximum update depth exceeded`（无限渲染循环）。

## 根因
进入白板后 Excalidraw 触发 `onChange` → `engine.syncFromScene()` → `emit('document'/'session')` → CanvasView 的
`store.listen` 回调（含 `setShapeTick(t=>t+1)` 等无条件 setState）→ 父组件重渲染 → `<Excalidraw>` 收到**不稳定的 props**
（`excalidrawAPI` 因 `onReady` 每次重建而变、`UIOptions` 内联对象每次新建）→ Excalidraw 重初始化并再次触发 `onChange` → 死循环。
注：`syncFromScene` 原实现每次 `onChange` 都**无条件** `emit`，空转也驱动 setState。

## 修复
- `ExcalidrawCanvas.tsx`：
  - `UIOptions` 提升为模块级常量 `EXCALIDRAW_UI_OPTIONS`（引用恒定）。
  - `handleAPI` 改为仅依赖 `[engine]`，`onReady`/`initialDocument` 收进 ref（`onReadyRef`/`initialDocRef`），引用绝对稳定。
  - 删除内联 `UIOptions` 对象。
- `CanvasEngine.ts` `syncFromScene()`：增加 dirty 跟踪，**仅当相机/几何/选中/工具确有变化时才写 atom 并 emit**；
  空转 `onChange` 不再触发 `emit→setState`。此为兜底，即使 Excalidraw 重渲染仍反复 `onChange` 也不会再 setState 重渲染。

## 验证
- `tsc --noEmit` 全项目 0 错误（canvas-v2/engine 无新增）。
- 无头引擎测试 `engineNodeTest.ts` 25/25 全过（syncFromScene 改动未破坏几何同步/撤销重做/迁移等）。
- dev server（5173）相关模块转译 HTTP 200，无报错。
- 因沙箱无浏览器自动化，未能跑真实浏览器交互；修复基于结构分析与测试。
