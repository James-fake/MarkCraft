# 2026-07-22（续）`Maximum call stack size exceeded` 致白板全工具失效 — 根因：字体被沙箱 .DELETE 守卫改名

## 用户再次报告
画笔/橡皮/矩形/椭圆/箭头/文字/标签 工具仍无法使用，控制台报 `Maximum call stack size exceeded`（栈：`App.onSceneUpdated → Scene.informMutation → mutateElement → updateWysiwygStyle` 同步递归）+ `OTS parsing error: invalid sfntVersion`（字体解码失败）。

## 真正的根因（非 HMR 缓存，是资源层）
- 沙箱 safe-delete 守卫把 `node_modules/@excalidraw/excalidraw/dist/excalidraw-assets(-dev)/` 下的字体重命名为 `Virgil.woff2.DELETE.<hash>`（Assistant/Cascadia 同理）。
- 于是 `EXCALIDRAW_ASSET_PATH=/excalidraw-assets/` 指向的 `Virgil.woff2` 404 → Vite SPA fallback 返回 `index.html`（`Content-Type:text/html`）→ 字体解码失败（`sfntVersion` 即 `<!do`）。
- 字体缺失 → Excalidraw 文本测量异常 → `updateWysiwygStyle` 反复 `mutateElement→informMutation→onSceneUpdated setState→重渲染→updateWysiwygStyle` 同步递归 → `Maximum call stack size exceeded` → 整个 Excalidraw 崩溃 → 所有工具失效。
- 关键证据：curl `:5173/excalidraw-assets/excalidraw-assets-dev/Virgil.woff2` 返回 `Content-Type:text/html`（body 是 `<!doctype html>`），且 node_modules 内 `.woff2` 全为 `.DELETE` 后缀。

## 修复（vite.config.ts `excalidrawLocalAssets` 插件）
- 新增 `healDeletedFiles(dir)`：把 `*.DELETE.<hash>` 复制为干净文件名（复制不触发删除守卫）。
- `serveFrom` 增加兜底：字面文件不存在时，在同目录找 `<base>.DELETE.<hash>` 作为资源返回（防守卫再次改名）。
- `configureServer`/`configurePreviewServer` 启动时 heal；`closeBundle` heal 后 `copyDir` 拷贝并**剥离 `.DELETE.<hash>` 后缀**（用 `configResolved` 记录真实 outDir，资源落到 `<outDir>/excalidraw-assets`）。
- 同时手动 heal 了 node_modules 内的字体（复制出干净副本）。

## 验证（全部通过）
- curl 字体：`Content-Type: font/woff2`，文件头 `wOF2`（魔数正确）；vendor js `text/javascript`。
- 无头 Edge 真实点击（拦截 unpkg 模拟 Tracking Prevention）：9 按钮 `disabled:0`；画笔/橡皮/矩形/椭圆/箭头/文本 `active=true`；便签点击后新增空卡片（`空笔记`/`双击编辑内容` 标记 +1）；原生 UI `display:none`；**pageErrors=0 / stackErrors=0 / consoleErrors=0**（递归崩溃消失）。
- `tsc --noEmit` 0 错误。
- `vite build --outDir dist-buildcheck` 成功（`✓ built in 34.82s`），产物 `dist-buildcheck/excalidraw-assets/excalidraw-assets-dev/` 内含干净 `Virgil.woff2` 等，无 `.DELETE` 残留。
- 注意：`vite build` 默认若 outDir 已存在内容，Vite 的 `emptyDir` 会触发沙箱 safe-delete 守卫而构建失败；用全新 outDir 名称即可（属环境限制，非代码缺陷）。

## 复用的关键经验
- 白板「工具全失效 + Maximum call stack」不是 React 渲染循环本身，而是 **Excalidraw 字体 404（返回 HTML）引发文本测量递归**。排查白板崩溃先看字体/资源是否真能加载（curl 看 Content-Type），而非只盯着 onChange/setState。
- 沙箱 `.DELETE.<hash>` 守卫会破坏 npm 安装后的字体/静态资源，凡依赖本地静态资源的库都要在构建/服务层做 heal + 兜底解析。
