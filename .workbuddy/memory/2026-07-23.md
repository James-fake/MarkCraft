# 2026-07-23 工作记录

## Canvas 白板「Maximum call stack」第三类根因（致命）— 已修复

### 现象
进入白板后，工具栏（画笔/橡皮/矩形/椭圆/箭头/文字/便签…）全部点击无响应，控制台循环报 `Maximum call stack size exceeded`，栈为 `updateWysiwygStyle → mutateElement → informMutation → onSceneUpdated → …`，且 `App.tsx:1337 Warning: An update (setState…) was scheduled from inside an update function`。

### 真因（与之前归因的外网字体/资源无关，是独立的真正根因）
Excalidraw 的 `appState.zoom` 必须是 **`{ value: number }` 对象**，但本项目多处把 zoom 当作**裸数字 number** 写回：
- `CanvasEngine.setCamera` / `zoomToBounds` / `zoomToFit` 调 `api.updateScene({ appState: { zoom: <number> } })`；
- `loadDocument` 调 `updateScene({ appState: { zoom: data.viewport.zoom } })`，而初始文档 `canvasPersistence.ts` 的 `viewport.zoom` 就是裸数字 `1`；
- 序列化时 `serialize` 也存 `zoom: app.zoom ?? 1`（app.zoom 是对象，存成对象没问题，但读取侧 `app.zoom ?? 1` 误把对象当数字用）。

结果 `appState.zoom` 变成 `1`（number）。Excalidraw 坐标换算 `viewportCoordsToSceneCoords` 用 `zoom.value`（此时为 `undefined`）做除法 → 新建文本元素 x/y = **NaN**。而 `mutateElement` 的 `didChange` 守卫用 `element.x === value` 比较，**`NaN === NaN` 永远为 false** → 每次文本编辑的 `updateWysiwygStyle` 都判定「有改动」→ 无限 `informMutation` → 同步递归栈溢出，整块白板崩溃。

> 注：之前几轮把同类报错归因于 unpkg 外网字体 / `.DELETE` 守卫，那些是另一类（字体 404）现象；本次无头验证字体已正常（`Content-Type: font/woff2`），真正触发文本编辑递归的就是这个 NaN zoom 坐标 bug。

### 修复（src/features/canvas-v2/engine/CanvasEngine.ts）
- 新增 `asZoom(z)`：把裸数字 / `{value}` / 非法值统一归一化为 `{ value: number }`。
- 新增 `zoomValue(z)`：安全读取 zoom 数值（兼容对象与裸数字）。
- 所有**写入** `appState.zoom` 处（`setCamera` `zoomToBounds` `zoomToFit` `loadDocument`）改用 `asZoom(...)`。
- 所有**读取** `app.zoom` 处（`syncFromScene` 相机、`serialize`/`serializeState` 持久化、`screenToScene` 坐标换算）改用 `zoomValue(...)`。
- 顺带修：① `setCurrentTool` 内 `this.api.setActiveTool` 在 `queueMicrotask` 闭包里 `this.api` 可能为 null → 改为 `const api = this.api` 后使用（消 tsc TS2531）；② `CanvasView.tsx` 去掉未使用的 `setShapeTick` 解构（消 TS6133）。

### 验证
- 无头 Edge（拦截 unpkg）+ 真实鼠标：9 个工具（选择/拖拽/画笔/橡皮/矩形/椭圆/箭头/文本/便签）逐个拖拽/点击，每工具 `Maximum call stack` 错误数 **0**；文本编辑 `ERRORS after text edit: 0`。
- 新建文本元素 x/y 为有效数值（如 572/424），`appState.zoom` 恢复为 `{value:1}`。
- `tsc --noEmit` 全项目 0 错误。
- 已删除本轮及历史遗留的临时冒烟/验证脚本（verify_*.cjs / smoke-*.html / __*Smoke.tsx / __subSmoke.tsx），并移除排查期加的 `window.__exapi` 暴露与 `[LOADEDELS]` 调试日志、CanvasView 的 `[A/B-TEST]` 注释。

### 铁律（留给以后）
凡经 `excalidrawAPI.updateScene({ appState: { zoom } })` 写缩放，zoom 必须是 `{ value: number }`，绝不可传裸数字。`appState.zoom` 永远用 `zoom.value` 读取。任何「白板工具全失效 + Maximum call stack」先查 `appState.zoom` 形状与新建元素 x/y 是否为 NaN（JSON 序列化 NaN 显示为 null，别被骗）。

## Canvas 橡皮擦改为「局部擦除」（2026-07-23 续）

### 需求
原 Excalidraw 原生橡皮擦是「整元素删除」——一笔划过凡是相交的整条 free-draw（画笔）路径即被删掉。用户要求改为只擦经过位置的绘制内容（局部擦除），与常规画图工具一致。

### 方案（已实现）
- 橡皮擦不再走 Excalidraw 原生 eraser 交互，改为 `ExcalidrawCanvas` 中的透明覆盖层 `EraserOverlay`（仅当 `engine.getCurrentToolId()==='eraser'` 时挂载，覆盖层 `pointer-events:auto`、`zIndex:6`、`cursor:none`，拦截指针使原生 eraser 收不到事件）。
- 覆盖层沿指针轨迹调用 `CanvasEngine.eraseSegment(from, to, radius)`：
  - **free-draw（画笔）笔画**：把被擦线段「半径 capsule」范围内的点剔除，存活点重新分段成多条子 free-draw 元素（local 擦除，保留两端）；残留 <2 点的片段丢弃。
  - **其它图元**（矩形/椭圆/箭头/文本/直线等，非卡片）：胶囊与（按半径外扩的）包围盒相交则整元素删除（矢量图形无法局部擦，整删符合直觉）。
  - **卡片代理矩形**（customData.cardType）不擦。
- 橡皮半径跟随 `appState.currentItemStrokeWidth`（至少 4），覆盖层显示跟随指针的圆形光标（屏幕直径 = 2*radius*zoom）。
- 坐标用引擎既有 `screenToPage`（与 Excalidraw `viewportCoordsToSceneCoords` 公式一致：`(client-offset)/zoom - scroll`）。
- 擦除经 `updateScene` 写回，期间置 `applyingRemote=true` 跳过本次 `onChange` 同步回写防重入，并 `scheduleHistory()` 支持撤销。

### 关键文件
- `src/features/canvas-v2/engine/CanvasEngine.ts`：新增模块级几何辅助 `distToSegment` / `segmentsIntersect` / `segmentIntersectsRect`，公共方法 `getZoom()` 与 `eraseSegment(from, to, radius)`。
- `src/features/canvas-v2/engine/ExcalidrawCanvas.tsx`：`EraserOverlay` 子组件（仅 eraser 工具时渲染，带 `data-eraser-overlay` 便于测试），并在空白点击处理器中排除 eraser 工具避免误触侧栏折叠。
- `src/features/canvas-v2/components/BottomBar.tsx`：橡皮按钮 `title='橡皮'`（已存在，无需改）。

### 验证
- 无头 Edge（拦截 unpkg）：画 1 条 82 点水平画笔线 → 橡皮垂直擦中段 → 结果笔画被分成 **2 段**（81 点，中段出现 ~11 单位空隙），两端均保留，未整条消失；`Maximum call stack` 错误数 0，console 错误 0。
- `tsc --noEmit` 0 错误。临时验证脚本 `verify_eraser_test.cjs` 已删除；`window.__exapi/__engine` 临时暴露已移除（保留 `data-eraser-overlay` 作为稳定测试钩子）。

### 橡皮光标「看不见」修复（2026-07-23 续）
- **现象**：橡皮擦能正常局部擦除，但移动时看不到光标（因覆盖层 `cursor:none` 把系统光标也藏了，而自定义圆圈太淡）。
- **真因**：原 `EraserOverlay` 光标圆圈样式为 `1.5px solid rgba(20,20,20,0.55)` + `background rgba(20,20,20,0.06)`，在白底上 6% 填充几乎不可见；且初始 `opacity` 未显式置 1、仅在 `moveCursor` 时定位，首次进入前停在 (-100,-100)。
- **修复**（`ExcalidrawCanvas.tsx`）：
  - 光标改为 `border:2px solid rgba(30,30,30,0.92)` + `background rgba(30,30,30,0.10)` + `boxShadow: 0 0 0 2px rgba(255,255,255,0.9), 0 0 0 3px rgba(0,0,0,0.25)`（白+暗双层光晕，深浅背景都可见）；`boxSizing:border-box`；内部加 4px 中心准星 div。
  - 显示直径下限提到 `max(14, radius*2*zoom + 8)`（原 `max(6, …)`，过小）。
  - 初始 `opacity:0`（避免停在 -100,-100 的残影），`moveCursor` 时置 `1`；新增 `onPointerEnter` 在指针进入覆盖层即定位+显示（不依赖首次按下）。
- **验证**：无头 Edge 实测光标 `width/height=16px`、`opacity=1`、`border=2px`、圆心精确跟随鼠标 (900,450) 且在视口内；`tsc` 0 错。临时 `verify_cursor_test.cjs` 已删。

### 橡皮按钮右键「清空全部画笔笔迹」滑动条（2026-07-23 续）
- **需求**：右键橡皮按钮 → 按钮正上方弹出滑动条；拖到最右端 → 一键清除白板所有画笔笔迹（free-draw）；松开后/点击外部自动收起。
- **实现**：
  - `CanvasEngine.clearBrushStrokes()`：过滤 `el.type !== 'freedraw'`，保留卡片代理矩形与其它图元；`applyingRemote` 标记 + `updateScene` + `scheduleHistory`。
  - `EraserClearSlider.tsx`（新建）：自定义拖拽滑块，进度填充（accent 渐变，接近末端变红告警），拇指跟随；拖到阈值 `COMMIT_THRESHOLD=0.95` 立即 `onClear`；未达阈值松手回弹到 0（确认式）；Esc 收起。
  - `BottomBar.tsx`：橡皮按钮加 `onContextMenu`（左键仍切橡皮工具）；`eraserClear` 状态记录按钮坐标；portal 渲染滑动条（遮罩 z9998 + 滑块 z9999）+ `onClearBrushStrokes` 回调接 `editorRef.current.clearBrushStrokes()`。
- **关键坑（已解决，重要）**：
  1. **堆叠上下文**：滑动条最初 portal 到 `document.body`，被整体压在 Excalidraw 画布之下（`elementFromPoint` 返回 canvas），导致事件穿透画布误绘、滑块收不到事件。改为 portal 到 `.canvas-v2-root`（白板根容器，位于画布之上）即解决。
  2. **Excalidraw 在 document 级监听 pointer**：自定义滑块拖拽会被当成画布绘制。解决：滑块根节点 + 外部遮罩用**原生** `addEventListener` 在冒泡阶段 `stopPropagation`（React 合成 `stopPropagation` 拦不住 document 原生监听）；且滑块全程用**原生** pointer 监听（因 portal 在 body/#root 外，React 17+ 委托在 #root，portal 子元素合成事件不可靠）。
  3. **提交阈值**初设 0.985 过严（拖到轨道右端内缩 4px 仅 0.9816 → 不触发）；降到 0.95 容差更合理。
- **验证**：无头 Edge 实测——右键弹出（滑块在画布之上）、画 1 条画笔→拖到末端→场景 freedraw 0、滑动条自动隐藏、点击外部收起、`Maximum call stack` 0；`tsc` 0 错。临时 `verify_eraser_clear_test.cjs` 已删。

## Canvas 箭头「点击卡片连线 + 持续绑定」（2026-07-23 续）

### 需求
点箭头工具 → 悬停卡片高亮 → 点卡片A 作为起点 → 点卡片B 作为终点 → 自动生成绑定连线；移动任一端卡片时连线端点始终跟随卡片（持续绑定）。

### 方案（已实现）
- **交互层 `ArrowLinkerOverlay`**（`src/features/canvas-v2/engine/ExcalidrawCanvas.tsx`，仿 `EraserOverlay` 模式）：仅当 `engine.getCurrentToolId()==='arrow'` 时挂载，覆盖层 `pointer-events:auto`/`zIndex:6`/`cursor:crosshair`（卡片在 arrow 工具下 `interactive=false` → pointer-events:none，由本层接管）。
  - `onPointerMove`：用 `engine.screenToPage` + `engine.getShapesAtPoint` 命中卡片 → 高亮（紫框）；`onPointerDown`：点卡片A 设为起点、再点卡片B 调 `engine.createBoundArrow(A,B)` 后重置起点（点空白/同卡取消）；起点→光标画虚线预览。
  - 顶部提示条「点击卡片作为连线起点 / 已选起点，点击另一张卡片完成连线」。
- **引擎层**（`CanvasEngine.ts`）：
  - 模块级 `edgePoint(box, target, gap)`：计算卡片边界朝另一卡片中心方向、外推 gap 的点（连线吸附卡片边缘而非插入内部）。
  - `createBoundArrow(fromId, toId)`：在两张卡片代理矩形间生成 Excalidraw `arrow` 元素，写 `startBinding/endBinding = {elementId, focus:0, gap:8}` 与两端 `strokeColor:'#6366f1'`、两端卡片 `boundElements:[{type:'arrow',id}]`；同方向重复连线返回 null 去重。
  - `refreshArrowsForCard(cardId)`（私有）：重算所有绑定到该卡片的箭头几何（两端边界点），在 `updateShape` 中调用 → **移动卡片时连线端点跟随**。
  - 箭头元素加 `customData:{ relationType:'reference', boundArrow:true }`；`deleteShapes` 已会连带删除绑定箭头（沿用既有逻辑）。

### 关键文件
- `CanvasEngine.ts`：`edgePoint` + `createBoundArrow` + `refreshArrowsForCard`；`updateShape` 末尾调 `refreshArrowsForCard`。
- `ExcalidrawCanvas.tsx`：`ArrowLinkerOverlay` 组件 + 渲染分支 `{tool==='arrow' && <ArrowLinkerOverlay/>}`。
- `BottomBar.tsx`：箭头按钮 `title` 改为「箭头：点击卡片作为起点，再点另一张卡片连线」。
