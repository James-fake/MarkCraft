## Canvas 白板「撤销/重做按钮点击无效果」根因修复
- **真因**：`CanvasEngine.scheduleHistory()` 在 400ms 防抖后把快照写入 `undoStack` 并 `canUndoAtom/canRedoAtom.set(...)`，但**从不 emit**。工具栏的 `canUndo/canRedo` React 状态只在 `editor.store.listen(updateState)` 收到 `emit('document'|'session')` 时刷新；而 emit 发生在 `onChange`/dirty 时刻（早于 400ms 后的快照落盘）。结果：快照已可撤销，但按钮仍停在旧的 `disabled` 值 → 点击撤销/重做被 disabled 吞掉，表现为「点击无任何效果」。
- **修复 1（主因）**：`scheduleHistory` 写原子后 `emit('session')`，使 `updateState` 及时读到 `canUndo/canRedo` → 按钮可用态实时刷新。
- **修复 2**：`loadDocument` 末尾以「加载后初始状态」作为基线快照 `undoStack=[serializeState()]`，使**首个编辑也可撤销**（之前首个编辑无法撤销）。
- **修复 3**：`restoreState` 的 `updateScene` 的 `zoom` 改走 `asZoom(vp.zoom)`（与全工程一致，避免裸数字 zoom）；并把 `restoreState` 改为 `try/finally`，确保 `updateScene` 万一抛错时 `applyingRemote` 必复位（否则会卡死后续所有 `syncFromScene`/历史记录）。`undo()/redo()` 末尾也补 `emit('session')`。
- **验证**：扩展 `engineNodeTest.ts` 第 [12] 节（基线快照、canUndo 随编辑变 true、emit 触发、撤销回到基线、重做恢复）全过；`tsc --noEmit` 0 错。
- **注意**：测试桩 `makeFakeApi.updateScene` 原先是 merge 语义（与真实 Excalidraw 的「整体替换」不符），已改为替换，否则 undo 恢复不删元素、测试误报。
- 临时 `verify_undo_test.cjs`/`engdbg.cjs`/`engineNodeTest.bundle.cjs` 已删；`engineNodeTest.ts` 保留。

## Canvas 白板「撤销一次清空全部」根因修复（2026-07-24 续）
- **真因（独立于上一轮）**：历史快照只由 `scheduleHistory()` 经 400ms 防抖落盘，而 `scheduleHistory` 仅在 `syncFromScene` 的 `dirty` 标志为真时触发；`dirty` 只由「相机/卡片几何/卡片选中/工具」变化翻转。原生绘制/文本/移动等只改 Excalidraw 图元（非卡片、工具已保持），`dirty` 全程为 false → `scheduleHistory` 仅在第一笔（工具由 select→draw）被调用一次；后续每笔都不触发 → 历史栈只有 `[基线]`，一次撤销直接回退到基线，整页清空。
- **修复**：改以「场景内容指纹」（`sceneSignature()` = 各图元 `id:version:isDeleted`）判定真实增删改；并用 Excalidraw 手势字段 `draggingElement/editingElement/editingTextElement/resizingElement/rotatingElement` 把一次连续手势收敛为**一条**历史条目（手势结束即 `commitAfterState()`，而非等 400ms 防抖合并多笔）。`scheduleHistory()` 加 `if (gestureActive) return` 防止手势期间重复提交；`commitAfterState()` 仅当与上一条不同才入栈。
- **模型**：保持 after-state 累积模型（栈顶=最近操作后状态，撤销回退上一条），`undo()/redo()` 逻辑不变。新增字段 `lastSceneSig / gestureActive`；`loadDocument`/`restoreState` 复位它们并刷新 `lastSceneSig`。
- **验证**：扩展 `engineNodeTest.ts` 第 [13]（3 笔间隔>450ms，逐步撤销）、[14]（3 笔间隔 60ms 模拟用户快速连画 + 重做）全过；修复前 [13] 实测 `undoStack.length===1`、撤销一次清空——已复现并修复。`tsc --noEmit` 0 错。
- **铁律**：经 `syncFromScene` 写历史绝不能依赖 `dirty` 标志；原生图元的增删改必须靠 `sceneSignature` 指纹 + 手势边界收敛，否则快速连续操作会被 400ms 防抖合并成单条历史，导致「一次撤销清空全部」。

## Canvas 白板「首笔画笔无法撤销」根因修复（2026-07-24 续 2）
- **真因**：Excalidraw 把进行中的**多段图元**（画笔 free-draw / 直线 / 箭头）挂在 `appState.multiElement`，而**不是** `draggingElement`。`syncFromScene` 的手势边界只检查 `draggingElement/editingElement/editingTextElement/resizingElement/rotatingElement`，漏掉 `multiElement` → 画笔绘制期间 `gestureActive` 始终为 false，收笔时不触发即时 `commitAfterState()`，只能靠 `sceneSignature` 防抖；而旧指纹仅 `id:version:isDeleted`，收笔时 version 未必变化、仅 points 变长 → `sceneChanged` 漏判 → 完全不提交 → `canUndo` 恒为 false。表现为「首笔画笔后撤销不可用，要先加卡片/画别的图形（本身能撤销）才有第二条历史才可撤销」。
- **修复 1（主因）**：`syncFromScene` 手势边界补 `app.multiElement`，画笔/直线/箭头绘制期间 `gestureActive=true`、收笔（multiElement 清零）即收敛为「一条」历史，与矩形等图形行为一致，**首笔即可撤销/重做**。
- **修复 2（防御）**：`sceneSignature()` 指纹纳入 `type + 几何(x,y,w,h) + 点数`，使「仅 points 变长、version 未变」也能被防抖正确识别为内容变化。
- **修复 3（防御）**：`attach()` 内若 `undoStack` 为空（首次进入未走 `loadDocument` / `initialDocument` 为空）自动以当前场景播种基线，避免「首笔提交后栈深=1 → canUndo 恒 false」。
- **验证**：`engineNodeTest.ts` 新增 [15a]（仅 attach 无 loadDocument，首笔画笔即可撤销+重做）、[15b]（已 loadDocument，首笔+第二笔各自独立成历史、逐步撤销）全过；原 [13][14] 不受影响；`tsc --noEmit` 0 错。
- **铁律**：手势边界必须包含 `appState.multiElement`（Excalidraw 多段图元的进行中载体）；写历史不能只依赖 `version` 变化，几何/点数也是内容变化信号。

## Canvas 白板「首笔画笔无法撤销」根因**再修复**（DOM 指针手势，2026-07-24 续 3，最终版）
- **上一轮为何没修好**：`multiElement` 前提**错了**。实测 `node_modules/@excalidraw/excalidraw@0.17.6` 源码，进行中的 freedraw 挂在 `appState.draggingElement`（`draggingElement.type==="freedraw"` 多处命中），**不是** `multiElement`（后者仅用于 line/arrow 多点点击）。而 `draggingElement` 本就在手势检测里 → 加 `multiElement` 无效。真正问题是：`onChange→queueMicrotask→syncFromScene` 的时序可能错过 `draggingElement` 清零的瞬间，收笔那次 sync 若仍读到旧 appState，则 `gestureActive` 不翻回、不 `commitAfterState`，且此后无更多 onChange → 首笔永不提交。靠猜 Excalidraw 内部字段本质不可靠（随版本变化）。
- **最终修复（不依赖 Excalidraw 内部字段）**：新增 DOM 指针手势边界作为**权威提交信号**。
  - `CanvasEngine` 新增 `pointerGesture` 标志 + `pendingCommit` 句柄 + `beginPointerGesture()/endPointerGesture()`。`begin` 置位并清待提交；`end` 复位并经 `setTimeout(0)`（晚于同轮所有微任务、确保场景已含最终图元）执行 `commitAfterState()`。
  - `ExcalidrawCanvas.tsx` 新增一个 `useEffect`：在容器上以 **capture 阶段**（`addEventListener(..., true)`）监听 `pointerdown→begin`、`pointerup/pointercancel→end`，并在 `window` 上兜底 up/cancel（拖拽越界）。capture 保证即使 Excalidraw 冒泡阶段 `stopPropagation` 也能收到；覆盖画笔/几何/文本/橡皮擦覆盖层/箭头覆盖层/卡片拖拽等所有指针操作。
  - `syncFromScene` 的 `gestureNow` 改为 `this.pointerGesture || (draggingElement||multiElement||...)`；`scheduleHistory()` 改为 `if (this.pointerGesture || this.gestureActive) return`。`attach/loadDocument/restoreState` 均复位 `pointerGesture` 并清 `pendingCommit`。
- **验证**：`engineNodeTest.ts` [15a]/[15b] 改为经 `begin/endPointerGesture` 驱动并**刻意不清 draggingElement**（模拟最坏时序）；新增 [15c]（全程无任何 appState 手势字段，仅 DOM 手势也能提交历史）。全部通过；[13][14] 不受影响；`tsc --noEmit` 0 错。
- **铁律（更新）**：白板历史提交的边界**以 DOM 指针 capture 事件为准**，不要依赖 Excalidraw appState 内部字段（`draggingElement/multiElement/newElement` 因版本而异、且 onChange 时序不可靠）。收笔提交用 `setTimeout(0)` 让场景先落定。

## 画笔撤销「按钮点不动 / 红色禁止图标」终极根因（emit scope 不匹配，2026-07-24 续）
- **现象**：画笔画完，hover 撤销按钮显示红色禁止图标（= disabled 的 `cursor:not-allowed`），点击无效；先加卡片/画别的图形后画笔才可撤销。
- **真根因（与手势边界无关，是 emit scope 不匹配）**：`commitAfterState()` 原来**只 `emit('session')`**；而 `CanvasView.handleMount` 里 `setCanUndo/setCanRedo`（`updateState`）只挂在 **`document` scope** 监听器上，`session` 监听器仅同步 zoom/选中/工具、**不碰 canUndo/canRedo**。纯画笔绘制期间 `syncFromScene` 的 `dirty` 恒为 false（画笔不改相机/卡片几何/选中/工具）→ 全程**无 `emit('document')`** → 引擎 `canUndoAtom` 虽为 true，但 React 的 `canUndo` 仍是旧的 false → 按钮 `disabled`。先做别的操作会走 `emit('document')`，才顺带把按钮刷亮 → 解释「要先做别的画笔才能撤销」。
- **修复（`CanvasEngine.ts` `commitAfterState`）**：置位 canUndo/canRedo atom 后**同时 `emit('document')` 与 `emit('session')`**（原来只 session）。一行修复，覆盖所有历史提交路径（画笔/几何/卡片/防抖）。
- **回归测试**：`engineNodeTest.ts` 新增 [15d]——复刻 CanvasView 的两类监听器（document 刷 canUndo、session 不刷），断言画笔收笔后 document scope 监听被触发且此刻 `getCanUndo()===true`。全部通过；`tsc` 0 错。
- **铁律**：凡是会改变 `canUndo/canRedo/zoom` 等「工具栏响应式状态」的引擎变更，**必须 emit('document')**（因 CanvasView 的 `updateState` 只在 document scope 刷这些）。session scope 仅覆盖 zoom/选中/工具，不要指望它刷 canUndo。
