## 底部工具栏「更多」菜单点击不弹出的根因修复
- **现象**：点击底部工具栏「⋯ 更多」按钮，按钮亮起（is-active），但下拉菜单完全不出现。
- **真因（堆叠上下文）**：菜单用 `createPortal(..., document.body)` 渲染到 body，z-index 仅 60/61；而整个白板容器 `.canvas-v2-root`（`CanvasView.tsx:1697`）为 `position:fixed; zIndex:100`，同属 body 级堆叠上下文。root（100）整体盖在菜单（61）之上 → 按钮（在 root 内）可见且亮起，菜单却被 root 压在下面"看不见"。这正是 `EraserClearSlider` 此前改成 portal 到 `.canvas-v2-root` 所规避的同一类坑（其注释明确写"否则堆叠上下文被压在 Excalidraw 画布之下"）。
- **修复（`BottomBar.tsx`）**：
  1. 菜单 `createPortal` 目标由 `document.body` 改为 `(document.querySelector('.canvas-v2-root')) || document.body`（与橡皮滑动条一致；`.canvas-v2-root` 无 transform，不破坏 `position:fixed` 的视口坐标）。
  2. 菜单在其内部堆叠上下文的层级提到 overlay `zIndex:900`、菜单 `zIndex:901`（高于底栏 40、画布/卡片、FloatingToolbar 500、AutoLayout 500 等，低于橡皮滑动条 9998/9999）。
  3. 加固 `toggleMore`：去掉 `if(!moreOpen && ...)` 前置判断，只要按钮可点（ref 存在）就始终 `setMenuPos(...)`，杜绝 `menuPos` 为 null 导致菜单不渲染的隐患。
- **验证**：`tsc --noEmit` → TSC_EXIT=0；dev server 5173 HTTP=200，HMR 已热更。
- **铁律**：canvas-v2 内需要盖在画布/底栏之上的浮层（下拉菜单、滑动条、弹层）必须 portal 到 `.canvas-v2-root` 或自身 z-index 高于 root 的 100，否则会被整体压在白板容器之下而"消失"。不要 portal 到 `document.body` 后用低 z-index 试图浮起。

## 浮动工具泡（FloatingToolbar）智能避障定位
- **需求**：选中卡片时右上角的浮动工具泡位置固定，卡片相邻/触碰时会遮挡相邻卡片内容。要求菜单具备位置感知，自动避让其它卡片且不越界。
- **原状**：原 `useLayoutEffect` 只做侧栏避让 + 视口边界夹紧，永远固定在卡片右上角，无相邻卡片遮挡检测。
- **修复（`FloatingToolbar.tsx` `useLayoutEffect`）**：
  - 收集遮挡物：遍历 `editor.getCurrentPageShapes()`，排除选中形状自身与 `arrow` 类型（细线连接器不算内容），用与卡片同一变换公式 `vp.x + minX*z + camera.x` 把页面包围盒转成屏幕矩形，存入 `occluders`。
  - 枚举 6 个候选位（偏好序）：卡片右上(默认) > 左上 > 右下 > 左下 > 上居中 > 下居中；连线额外把"中点上方"作为首选。
  - 每个候选先经 `clampToBounds`（保留原侧栏避让 + 视口/画布边界夹紧，确保不越界、不压侧栏），再算与 `occluders` 的重叠总面积 `overlapArea`。
  - 选取：重叠面积最小者；面积相近（≤0.5px²）时取偏好序更靠前（prio 更小）者 → 优先"完全不遮挡"，否则"遮挡最少"。`showColorPicker/showMore` 在 deps 中，展开面板导致菜单变高时会重新选位。
- **验证**：`tsc --noEmit` → TSC_EXIT=0；dev server 5173 HTTP=200，HMR 已热更。
- **注意**：遮挡检测在每次相机/选区变化（含平移缩放每帧）遍历全页形状 × 6 候选，常规白板量级（数百形状）开销可忽略；若未来超大型画布卡顿，可对 occluders 做分页缓存。

## 卡片选中框层级修复（HTML 浮层选区框，覆盖 Excalidraw 原生选区）
- **需求**：选中卡片并移动到与其它卡片/内容重叠时，选中框（带缩放/拉伸手柄）应始终显示在最上层，不被遮挡；层级须高于所有白板内容（含被选中的卡片本身）；不影响现有选中/缩放/拖拽。
- **根因**：卡片是 HTML 浮层（`data-card-overlay`，z-index 5）；而带 8 手柄的选中框是 Excalidraw 为卡片代理矩形在**最底层画布（z-index 0）**绘制的原生选区。重叠时被上方 HTML 卡片盖住，表现为"选中框跑到背后"。画布像素无法单独提升层级，必须把选区框改为 HTML 元素渲染到浮层里。
- **修复**：
  - 新增 `src/features/canvas-v2/engine/SelectionFrame.tsx`：读取 `engine.getSelectedShapeIds()` + `getCamera()` + `getCurrentToolId()`；仅在选择/拖拽/橡皮工具下渲染（绘图工具下不显示，避免遮挡钢笔/矩形绘制）。为每张选中卡片渲染一个浮层选区框（`pointer-events:none` 本体 + 8 个 `pointer-events:auto` 缩放手柄），`zIndex:999` 高于所有卡片。
  - 框体尺寸严格包裹卡片边框盒：content-box 下卡片外缘 = `w+4`/`hVis+4`，左/上即 `(x+cam.x)*z` / `(y+cam.y)*z`（注意：卡片边框盒左/上边就在该处，勿再外扩 -2，否则与卡片 2px 选中边框形成双线）。
  - 8 手柄（nw/n/ne/e/se/s/sw/w）拖拽时按 `dx=(clientX-startX)/z`、`dy=...` 换算页面增量，调用 `engine.updateShape({id,x,y,props:{w,h}})` 写回几何；引擎统一负责代理矩形同步 + `refreshArrowsForCard` 箭头跟随 + 撤销历史，缩放与现有选中/拖拽完全兼容。折叠态笔记卡片锁定垂直尺寸（仅水平缩放）。
  - 手势边界由 `ExcalidrawCanvas` 的全局 `pointerdown(capture)/window pointerup` 监听统一收口（`begin/endPointerGesture`），本组件不自行调用，缩放即被记为一笔可撤销操作。
  - `CardOverlay.tsx` 在卡片列表后渲染 `<SelectionFrame engine={engine} />`（位于 `data-card-overlay` 内，不触发空白点击折叠，且层级高于卡片）。
- **验证**：`tsc --noEmit` → TSC_EXIT=0；dev server 5173 HTTP=200，HMR 已热更 `SelectionFrame.tsx`/`CardOverlay.tsx` 无报错。
- **铁律**：canvas-v2 中"需显示在卡片之上的选中框/选区"必须在 HTML 浮层（`data-card-overlay` 内，z-index 高于卡片）渲染，绝不能依赖 Excalidraw 画布层（永远在卡片之下）。原生选区被浮层框覆盖即可，无需隐藏。
- **修正（同一问题的二次修复）**：首次只加了 `SelectionFrame`（z 999）但**卡片浮层本身没有任何 z-index 管理**——卡片按 DOM 插入顺序堆叠，选中卡片不会置顶，于是出现「选中卡片本体压在别的卡片之下、而选区框在最上层」的层级不一致（用户反馈"修复失败"，两种表现：① 选区框被下方卡片遮挡；② 卡片本体在第二张卡片之下但选区框在最上层）。
  - 修复：`CardOverlay` 重构为 `CardLayer`（每张卡片独立组件，订阅自身 `isSelected`），按层级约定给浮层 wrapper 设 z-index：**非选中=1（保持原 DOM 顺序，互相层级不变）、选中/拖拽中=30（自动置顶）、`SelectionFrame`=999**。三者满足 `999 > 30 > 1` → 选区框永远在选中卡片之上、选中卡片永远在其它卡片之上，其它卡片相对层级不受选中影响。
  - 关键：不能在 `map` 里直接 `useValue`（hooks 数量随卡片数变化会触发 React 报错），必须用独立组件 `CardLayer` 承载选中态订阅。
  - 验证：`tsc --noEmit` → TSC_EXIT=0；dev server 5173 HTTP=200，HMR 重编译 CardOverlay 无报错。

## 卡片选中框层级 — 最终修复（选择框与卡片合并为统一组件）
- **前两次"修复失败"回顾**：① 仅加 z-999 兄弟节点；② 给 CardLayer 设 z 30/1 但选择框仍是独立兄弟节点。仍出现"框被下方卡片遮挡"或"框在顶但卡片本体在下方"的层级不一致。
- **根因**：选择框与卡片是分离的兄弟节点，各自算层级 + 多卡片 DOM 顺序下堆叠上下文脆弱，无法保证"框永远在选中卡之上、且选中卡永远在其它卡之上"的强一致。
- **最终方案（统一组件）**：把选择框作为**选中 `CardLayer` 的内部子元素**渲染。删除 `SelectionFrame.tsx`，逻辑内联进 `CardOverlay.tsx` 的 `CardSelectionFrame`。框与卡片共享同一 `CardLayer` 的 `transform:scale` / 堆叠上下文 / z-index（选中卡 z-30 > 其它卡 z-1；框在该卡内 z-4 高于卡片内容）→ 框天然在选中卡之上、且整张选中卡（含框）在其它所有卡之上，彻底消除两类错位。框用 `inset:-3` 自动包裹任意卡片类型；`2/zoom` 边框宽 + 手柄 `scale(1/zoom)` 保持屏幕恒定大小；本体 `pointer-events:none`、仅手柄可点，卡片拖拽不受影响。
- 配套：`OverlayCards.tsx` 三处（note/label/generic）移除自身"选中边框"（保留选中辉光阴影），避免与统一框重复描边；`isSelected` 仍用于拖拽逻辑与 label 迷你工具条。
- 验证：`tsc --noEmit` → 0；dev server 5173 HTTP=200，HMR 已热更 `CardOverlay.tsx`/`OverlayCards.tsx` 无报错。
- 铁律更新：见 MEMORY.md 第 4 条。

## 选中框视觉多层嵌套收敛（仅优化渲染层级，不改 z 序/交互）

- **修复（最小改动，保持 z 层级/边框/交互不变）**：
