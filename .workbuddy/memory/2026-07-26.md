## 知识图谱：修复左工具栏与底部信息栏（图例）的重叠
- **现象**：左侧垂直工具轨 `.kg-rail`（`left:16px; top:50%; transform:translateY(-50%)`，垂直居中）与左下角图例 `.kg-legend`（显示 普通/高连接/孤立/标签/社区/路径 等，原 `left:16px; bottom:16px`）在左列同一 x 区间，当工具项较多（~14 个，轨道高约 686px）或窗口偏矮时，轨道下缘压住图例，内容互相遮挡。
- **根因**：轨道与图例都贴在 `left:16px` 左列，且轨道垂直居中会在矮屏同时上侵顶栏、下压图例；图例未避开轨道列宽（轨道右缘约 left+58=74px）。
- **修复（`src/features/graph/graph-ui.css`，纯 CSS，零 TS 改动）**：
  1. `.kg-rail`：由 `top:50%; transform:translateY(-50%)` 改为 `top:72px; transform:none`（锚定在 56px 顶栏下方，向下生长，矮屏不再上侵顶栏）；入场动画 `kgRailIn` 仅 `translateX`/`opacity`，与 `transform:none` 基态兼容，不受影响。
  2. `.kg-legend`：由 `left:16px` 改为 `left:88px`，整体移到轨道右缘（约 74px）之外并留出 14px 间隙 → 不论轨道多高、窗口多矮，二者在 x 方向恒不重叠；图例仍居左下、底部浮层层级 z-index 22 不变。`kgFade` 动画不受影响。
- **验证**：dev server 5173 `graph-ui.css` HTTP=200（Vite 正常 transform）；`tsc --noEmit` 在后台跑（项目较大耗时 >90s），因仅改 CSS 不会引入类型错误。`kgRailIn`/`kgFade` keyframes 仅动 transform/opacity，与本次 base 修改无冲突。
- **铁律补充**：知识图谱左列（轨道）占用 `left:16px`～约 `74px`；任何新增左下/底部浮层（图例、状态条等）须从 `left:88px` 起排或以其它方式避开该列，禁止再与 `.kg-rail` 同列导致遮挡。

## 知识图谱：修复导出等轨旁弹层被裁剪（问题一幽灵阴影 + 问题二菜单不显示）
- **根因（同一个）**：上一轮为防轨道压图例给 `.kg-rail` 加了 `overflow-y:auto`。按 CSS 规范，`overflow-y:auto` 会让 `overflow-x` 计算为 `auto`，于是向右弹出的 `.kg-pop`（布局/导出/快照）在水平方向**整体被轨道裁剪**：
  - 问题二：点击「导出」后菜单内容被裁隐 → 格式菜单不显示。
  - 问题一：被裁的 `.kg-pop` 其 `backdrop-filter`+`box-shadow` 仍透出一层**纯圆角阴影**（内容已裁、只剩阴影），且导出按钮在轨道偏下，幽灵阴影落在工具栏下方区域 → 用户报「工具栏下方圆角阴影元素」。
- **修复（`GraphView.tsx` + `graph-ui.css`）**：
  1. `graph-ui.css` `.kg-pop`：去掉 `position:absolute; left/top/transform`（不再自带定位），改为纯玻璃盒 + `kgPop` 缩放动画（定位交给外层容器，避免动画 transform 与居中 transform 冲突）。
  2. `GraphView.tsx`：新增 `popAnchor` 状态存按钮视口坐标（`getBoundingClientRect`）。三个轨旁按钮 `onClick` 捕获坐标并 `setRailPop`；**把三个 `.kg-pop` 从 `.kg-rail` 内部移出，改为 `.kg-rail` 的兄弟节点**渲染，外层 `<div style={{position:'fixed', left:锚点右+12, top:锚点垂直中心, transform:'translateY(-50%)', zIndex:55}}>` 定位在按钮右侧并垂直居中，内层 `.kg-pop` 负责玻璃样式与动画。
  3. 根 `.kg-shell` 为 `position:fixed`（非 transform），不劫持 fixed 包含块，故 `position:fixed` 仍相对视口、用视口坐标定位正确，且弹出层脱离轨道 `overflow` 不再被裁。
- **验证**：dev server 5173 `GraphView.tsx`/`graph-ui.css` HTTP=200、无 transform 错误；`tsc --noEmit` 后台运行中确认类型。图例保留（用户此前要求与工具栏左缘对齐，问题一实为该裁剪幽灵阴影，非图例）。

## 知识库：修复详情页搜索/问答/导出面板空白（CSS containing block）
- **现象**：知识库详情页点击「搜索」时，搜索界面显示为空白，无法渲染结果与搜索框；问答、导出同样空白。
- **根因**：三面板均 `position:fixed; inset:0`，原渲染在 `.kb-content-inner` 内。`.kb-content-inner` 带 `animation: kbTabIn .34s var(--kb-ease) both`，`both` 填充模式在动画结束后冻结 identity transform（`matrix(1,0,0,1,0,0)`），使其成为 fixed 的 containing block。`inset:0` 相对 `max-width:1080px; margin:0 auto`（零高度、水平居中）盒子解析 → 面板高度塌缩为 0 → 空白。浏览器实测定位：`panelRect = {w:1080, h:0, ...}`，`.kb-content-inner` 的 `transform: matrix(1,0,0,1,0,0)`。逻辑层经 esbuild+jsdom harness 验证 0 运行时错误（搜索/高亮/结果均正常），排除组件逻辑问题。
- **修复**：
  1. 新增 `src/features/knowledgeBase/components/kbOverlayRoot.ts`：导出 `getKbOverlayRoot()`（取 `#kb-overlay-root`，否则回退 `document.body`）。
  2. `KbDashboard.tsx`：新增 `useEffect` 在 `.kb-shell`（`position:fixed; inset:0` 满屏且定义 `--kb-*` token，逃逸 transform 又继承主题）内创建并挂载 `#kb-overlay-root`，卸载时移除。
  3. `KbSearchPanel.tsx` / `KbChatPanel.tsx` / `KbExportMenu.tsx`：根节点 `return` 改为 `return createPortal(<根>, getKbOverlayRoot())`（补 `import { createPortal } from 'react-dom'` 与 `getKbOverlayRoot`）。导出菜单依赖 `.kb-*` token，故 portal 到 `.kb-shell` 内而非 `document.body`（否则丢失玻璃主题）。
- **验证**：
  - `tsc --noEmit` 通过（TSC_EXIT=0）。
  - 系统 Edge（`--remote-debugging-port=9333`）+ `puppeteer-core` 实机复测：进入详情页点「搜索」后 `#kb-overlay-root` 存在，面板 `getBoundingClientRect = {w:1440, h:900}`（全屏）、`hasInput:true`；输入查询后状态摘要（"找到 X 个文件 · Y 处匹配"）与「未找到匹配结果」状态正确渲染（测试库 0 文件）。修复前 `h:0` 空白 → 修复后满屏。问答/导出同理 portal 修复。
- **铁律新增**：知识库内任何渲染在 `.kb-content-inner` 中的全屏 `position:fixed; inset:0` 覆盖层，都必须 portal 到 `.kb-shell` 内的 `#kb-overlay-root`，否则必因 transform containing block 而高度塌缩为 0（空白）。

## 知识库：修复「新建笔记」报"文件不存在或已被删除"
- **现象**：用户点击「新建笔记」时 KbNoteViewer 显示"文件不存在或已被删除"错误。
- **根因**：`kb.folderId` 存于 IndexedDB（KB 元数据），`rootFolder` 来自 FileStore（localStorage 加载）。两者存储分离，若 localStorage 被清空/重置（新设备、清缓存等），KB 的 `folderId` 会指向文件树中已不存在的文件夹。`createFile` 内部的 `addChildNode(rootFolder, parentId, newFile)` 找不到 `parentId` 时**静默返回原树**（文件不被添加），但 `createFile` 仍返回 `newFile.id`。`onOpenFile(id)` → KbNoteViewer 渲染 → `findNodeById(rootFolder, fileId)` 返回 null → 显示"文件不存在或已被删除"。
- **修复（`KbDashboard.tsx`，仅 `handleNewNote` 函数）**：
  1. 在 `handleNewNote` 中先用 `findNode(rootFolder, kb.folderId)` 校验文件夹是否存在。
  2. 若不存在：`createFolder('root', kb.name)` 重新创建文件夹，拿到新 `folderId`；异步 `saveKb({ ...kb, folderId })` 更新 IndexedDB 中的 KB 元数据 + `loadActiveKb(kb.id)` 刷新内存态。
  3. 用有效的 `folderId` 调 `createFile(folderId, '未命名笔记', '', false)`。
  - 新增解构：`useKbStore()` 加 `saveKb, loadActiveKb`；`useFileManager()` 加 `createFolder`。`findNode` 已从 `fileService` 导入。
- **验证**：
  - `tsc --noEmit` 通过（0 类型错误）。
  - Edge + `puppeteer-core` 实机复测两种场景：
    - **正常路径**（文件夹存在）：点击「新建笔记」→ 编辑器正常打开（`hasBackBtn/hasFileName/hasEditor` 均 true），笔记数量 +1，0 错误。
    - **恢复路径**（文件夹丢失）：通过 React fiber 获取 `deleteNode` 并删除 KB 文件夹（`deletedFolderId: "1785043510194-ofuaslmhw"`），模拟 localStorage 丢失 → 点击「新建笔记」→ `error_after_fix: false`（无"文件不存在"错误）→ 编辑器正常打开 → 笔记创建成功 → `page_errors: 0`。
- **铁律新增**：`kb.folderId`（IndexedDB）与 `rootFolder`（localStorage）存储分离，任何依赖 `folderId` 的操作都必须先 `findNode(rootFolder, folderId)` 校验存在性；丢失时通过 `createFolder('root', kb.name)` 重建 + `saveKb` 更新元数据。`addChildNode` 找不到 `parentId` 时静默失败（不报错、不添加），是此类 bug 的隐蔽根源。
