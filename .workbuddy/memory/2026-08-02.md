## PDF 导出 Bug 修复（generatePdf 不落盘 / 0KB / 误跳打印页）
- 现象：选 PDF 导出 → 弹浏览器打印页；在文件所属文件夹尝试打开 → 打开错误；文件 0KB。
- 根因：① 旧 `generatePdf`（`src/features/export/utils/exportPdf.ts`）只用 `window.print()` 弹打印对话框，**不生成任何文件**；② `SaveAsModal.handleSave` 在 `saveLocation.type==='file'|'directory'`（File System Access）时 PDF 分支只调 `generatePdf`、**从不 `createWritable().write(blob)`**，导致 FSA 占位文件从不为真实内容，残留 0 字节被系统尝试打开 → 打开错误 + 误跳打印页。
- 修复：引入 `html2pdf.js`（用户确认方案），重写 `generatePdf` 用 `html2pdf().set(opt).from(离屏容器).outputPdf('blob')` 生成真实 PDF `Blob` 并返回（不再 `window.print`）；`SaveAsModal` 把 PDF 与其它格式统一为「生成 Blob → 写入 FSA / 浏览器下载」。空 Blob 抛错防 0KB 落盘。
- 验证：`src/features/export/utils/__tests__/exportPdf.test.ts`（5 passed）验证返回真实非空 Blob、`window.print` 未被调用、空 Blob 抛错、`buildPdfHtml` 含 TOC/页眉页脚。全量 `vitest run` **287 passed / 2 skipped**；`tsc --noEmit` 0 错误；`vite build` BUILD_EXIT:0（html2pdf 入 SaveAsModal 懒加载 chunk ~1.4MB，PWA 190 条预缓存）。
- 记忆已沉淀：MEMORY.md 新增「PDF 导出铁律」。

## PDF 导出 Bug 二次修复（点击打开后空白页）
- 现象：上一轮修复后 PDF 文件不再是 0KB，但双击打开是**白板（全空白页）**。
- 根因：`generatePdf` 用 `document.createElement('div')` 做离屏容器并 `position: fixed; left: -10000px` 后把**该 div** 交给 html2canvas。html2canvas 对 `position: fixed` 元素按**视口坐标**定位 → 内容被排到画布 x=-10000 处、落在被截图区域之外 → jsPDF 得到透明图像贴在白底上 = 全白 PDF。
- 修复：渲染容器改为**离屏 iframe（srcdoc）**——`idoc.open(); idoc.write(buildPdfHtml(...)); idoc.close()`，等待 `load` + `document.fonts.ready` + 所有 `<img>` 加载完成（带 2s 兜底超时）后，把 **`idoc.body`** 交给 `html2pdf().from(target)`。因截图目标是 iframe 内部文档，`body` 内部坐标恒为 (0,0)，外框位置无关 → 内容稳定入画。
- 验证：测试新增断言 `from()` 接收的渲染目标 `tagName === 'BODY'`（即离屏 iframe body 而非 off-screen div）；`exportPdf.test.ts` 5 passed；全量 `vitest run` 287 passed/2 skipped；`tsc --noEmit` 0 错误。dev server :5173 运行中（HMR 已生效）。
- 复用铁律更新：MEMORY.md「PDF 导出铁律」补充——**html2canvas 截 `position:fixed` 元素按视口坐标，off-screen 固定元素会白板；用离屏 iframe body 作为渲染目标**。

## 编辑器"打印"功能修复（编辑模式点打印预览显示无关内容/空白页）
- 现象：在**源码/编辑模式**点工具栏"打印" → 浏览器打印预览显示的是整个应用界面（工具栏/侧边栏/编辑器外壳），而非当前正在编辑的文件内容；或接近空白页。
- 根因（架构性）：打印入口有两条并行链路，内容来源不一致——
  - 键盘快捷键 `Ctrl+P`：`App.useKeyboardShortcuts({ onPrint: handlePrint })` → `handlePrint` = `printDocument(renderedHtml)`（renderedHtml = `useMarkdownRenderer(localContent)`，即当前文件渲染后的 HTML）→ **正确**。
  - 工具栏"打印"按钮：`sharedMoreItems` 的 `action: () => onPrint?.()` 读 `ctx.onPrint`，而 `ctx` 来自编辑组件自身 `EditorUIContext.Provider` 的 `editorUIValue`。源码模式下 `CodeMirrorEditor` 的 `modalsValue.onPrint` 被**硬编码为 `() => window.print()`**（WYSIWYG 模式 `TiptapEditor` 则用 `editor.getHTML()`，反而正确）→ 工具栏打印在源码模式直接 `window.print()` 整页应用 DOM，预览自然是"无关内容/空白"。
- 修复：把 App 的 `handlePrint` 正确链路**向下透传**到源码编辑器——
  1. `EditorLayout` 新增 `onPrint?: () => void` prop（App 调用处传入 `onPrint={handlePrint}`）；
  2. `CodeMirrorEditor` 新增 `onPrint?` prop，`modalsValue.onPrint` 改为 `onPrint ?? (() => window.print())`，并加入 `useMemo` 依赖数组；
  3. `EditorLayout` 渲染 `<CodeMirrorEditor onPrint={onPrint} />`；
  4. （连带清理）`MarkdownToolbar` 同步新增 `onPrint?` prop，`buildSharedMoreItems` 用 `props.onPrint ?? window.print()`，并由 `EditorSlots.EditorToolbarSlot` 透传 `onPrint={ctx.onPrint}`（双重保险，实际生效的是 CodeMirrorEditor 的 editorUIValue 路径）。
- 验证：`tsc --noEmit` 0 错误；`vitest run src/features/toolbar src/features/editor src/features/export` **108 passed**；dev server :5173 在线（HMR 已生效）。
- 复用铁律新增：MEMORY.md「打印功能铁律」——**编辑器打印必须走 App 的 `handlePrint`(`printDocument(renderedHtml)`) 渲染当前文件；不可在编辑器内部 `editorUIValue.onPrint` 硬编码 `window.print()`（会打印整页应用）**。各编辑器组件经 `EditorLayout` 注入 `onPrint`。
