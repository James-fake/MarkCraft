## 双链图谱：单击节点跳转笔记 + 「← 返回 双链图谱」+ 现场复原

**诉求**：图谱点击节点自动跳到对应笔记文件；跳转后的界面要有「返回」回到图谱。

**根因（真机实测，推翻「功能没做」的直觉）**：节点的 `onClick` **在真实浏览器里永不触发**。
`onNodePointerDown` 为拖拽把指针捕获到 `<svg>`，而**指针捕获会把随后的 click/dblclick 一并
重定向到捕获元素**——CDP 探针实测 `click.target = "svg.aurora-graph__svg"`（不是节点 `<g>`）。
jsdom 不实现捕获重定向，所以既有单测全绿、真机点节点毫无反应。这正是用户提这个需求的由来。
附带第二个坑：旧代码在 `onPointerUp` 里把 `dragRef` 置空**之后**，才在 click 里读
`dragRef.current?.moved` —— 判据恒为假，拖拽与单击本就无法区分。

**修复要点**：
- 单击改在 **pointerup** 上兑现（`dragRef.moved` 为假即单击）；补 **4px 拖拽阈值**
  `NODE_CLICK_SLOP`（手抖仍算单击，否则每次点击都变成拖动节点）。
- `onNodePointerDown` **只接受主键**：否则右键按下会开始拖拽并（在新逻辑下）触发跳转。
- `nodeGestureRef` 兜住「画布点空白清空选中」：被重定向到 svg 的节点 click 的 target 也是 svg，
  只看 target 会把「点节点」误判成「点空白」→ 选中态/信息卡刚出现就被自己清掉。
- file 节点 → `openNoteInEditor`（openFile + `setEditorReturn({view:'graph',label:'双链图谱'})`）；
  tag/folder 无跳转目标，保留信息卡（入口改为右键菜单「查看详情」）。
- 新增 `src/aurora/panels/kb/graphSession.ts`：图谱「空间现场」（节点坐标/视口/布局/模式/中心/选中）
  跨挂载记忆，模块级单例（同 `navReturn` 模式）。AuroraShell 按 view 渲染、无 keep-alive，
  GraphPanel 卸载即丢 useRef 里的坐标 → 返回后按环形布局 + `Math.random` 重新布点，
  观感等同「图被刷新」。搜索词/标签筛选属查询态，不入此列。
- EditorPanel `handleReturnToKb` → `handleReturnToSource`，复用既有「← 返回 XX」芯片承载图谱来源。

**验证（CDP 真鼠标事件 1600×950，14/14）**：单击 → 入场编辑器且打开的笔记与节点 label 一致；
芯片「← 返回 双链图谱」；返回后**逐节点「身份+几何」与点击前完全一致**（含 `<g transform>` 视口）、
原节点仍高亮；真实拖拽 120px 不跳转且节点确实被挪动；tag 节点单击出信息卡；点空白清空选中；
右键菜单 9 项含「查看详情」。脚本 `.workbuddy/cdp-graph-node-nav-verify.mjs`（报告 `graphnav-report.json`，截图 `graphnav-1..7-*.png`）。

**两个方法论教训**：
1. **「快照在冷启动索引填充期采集」会假失败**：本次一度报 `positionsIdentical: false`（3 个文件节点差 1.7–10px），
   加「等待图谱稳定（连续两次快照一致）」+ 改用「点击前瞬间」作比较基准后消除。另实测 `rAF total: 0`，
   力模拟**确实未自动运行**（挂载后坐标静止），排除了「模拟在漂」的猜测。
2. **单测用 `fireEvent.click` 在这类捕获型交互上是假路径**：节点单击测试改走
   `pointerdown → pointerup` 生产路径；且 jsdom 的 PointerEvent 回退实现不携带 `button/clientX`
   （`window.PointerEvent` 缺失 → 退化成 `Event`），需用 **MouseEvent 承载同名指针事件**才有属性。

**已知残留（未扩大改动面）**：节点 `dblclick` 同样被重定向到 svg，故 `onNodeDouble` 对真实指针不可达，
其实际入口是右键菜单「打开笔记」；tag 双击筛选由左栏标签芯片兜底。已在代码注释中标注。
