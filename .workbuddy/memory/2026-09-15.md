## 需求 N 返工：顶栏功能切换 tab 支持「在 tab 栏内」左右滑动

### 起因
用户追问「为什么我要求的功能 tab 切换栏内可以左右滑动的效果没有实现？」

**根因**：需求原话是「**顶栏的功能切换 tab，支持左右滑动**」= 在 **tab 栏本身内**横滑。
首轮把这句重构成了「**内容区**滑动切 Tab」，手势只绑内容区 → 用户抓 tab 栏滑动**毫无反应**。
CDP 对照实验 `diag-tabbar-vs-content.mjs` 定案：设置页 tab 栏内拖动 ❌ / 内容区拖动 ✅。
**教训**：需求里的方位词（「栏内」「顶栏」）是**手势起手区**的规格，不是修辞。重构需求前先确认起手区。

### 修复一：双点位绑定（`src/aurora/hooks/useSwipeTabs.ts`）
- 新增 `makeBind()` 工厂 → 同一套手势逻辑**同时**挂到「tab 栏 + 内容区」，共享
  `gestureRef`/`offsetRef`/`suppressClickRef`（pointerup 一结束 `activeRef` 复位，两份绑定不互扰）。
- `onClickCapture`：横滑松手后浏览器仍在 tab 按钮上派发 click → 会把刚滑到的 tab **又点回去** →
  `endGesture` 在 `|offset| > DIRECTION_SLOP` 时置 `suppressClickRef`，click 到来时吃掉一次。
- `measureRef`：吸附阈值恒按**内容区**宽度算（32%）。手势可能从窄 tab 栏起手，
  若用 tab 栏宽会把「轻轻一划」误判翻页。
- 原 `bind` 字段保留向后兼容；四面板（设置/知识库/博客/白板）全部改用 `makeBind()`。

### 修复二：博客 tab 行完全滑不动（独立缺陷）
- `enabled` 被绑到 `panelOpen`，而浮层默认收起（`useState(false)`）→ `onPointerDown` 直接 return。
- 改 `enabled: true`（tab 行常驻可见 → 手势就该常驻可用）；位移目标收起时为空，由 hook 内空判兜住。
- `measureRef` 从「浮层内容体」（收起时不挂载 → `ref.current === null`）换成常驻预览区 `.aurora-blog__stage`，
  否则会退回用 **99px** 的 tab 行做基准。
- KB / 白板**无**此门控问题（检查过）。

### 修复三：tab 栏缺少手势区声明（CSS）
手势绑上 tab 栏后它就是起手区，`touch-action` 仍是 `auto` 会让触摸/触控板的横向位移被浏览器
当**页面横滚/回退手势**抢走；且 `onWheel` 里的 `preventDefault()` **无效**
（React 17+ 以 passive 监听注册 wheel）→ 只能靠 CSS 声明轴向。
- 四面板 tab 栏统一补 `touch-action: pan-y` + `user-select: none`
  （原先**只有白板** `.aurora-csp__tabs` 有 `pan-y`）。
- 加 `[data-swiping] { cursor: grabbing }` 作跟手期光标语言。
  **静止态刻意不设 `cursor: grab`**：tab 是按钮，静止态 grab 会与点击语义打架。
- KB 的 tab 栏是 `overflow-x: auto`（tab 多时溢出）：触摸下溢出内容由「横滑切 tab」抵达，
  桌面鼠标仍可 Shift+滚轮横滚 —— 取舍已写进 CSS 注释。

# 需求 N 第三轮：整排 tab 跟手（「按住 tab 方框左或右可以滑动」）

### 用户反馈（第三次）
「在 tab 栏本身内横滑的效果**还是没有显示出来**，我要的效果鼠标按住 tab 方框左或右可以滑动。」

**第二轮其实"能识别"，但视觉上等于没动** —— 这是本轮关键认知：
手势挂对了 ≠ 用户看得见。判断"做没做"必须量**视觉位移像素**，不能只看 `data-swiping`。

### 实测定位（新探针 `probe-swipe-drag-amplitude.mjs`）
| 拖动 | 手势 | 内容层位移 | **tab 方块位移** | 松手 |
|---|---|---|---|---|
| 按住方块慢拖 150px | ✅ 识别 | 25.2px | **0.7px** | ❌ 不切换 |
| 快速甩 150px | ✅ 识别 | 25.2px | **0.7px** | ❌ 不切换 |
| 大幅拖 420px | ✅ 识别 | 25.2px | **2.0px** | ❌ 不切换 |

两个坏点（都在**参数**，不在绑定）：
1. 方块位移 = `--swipe-progress × 6px`，而 progress = `offset / 内容区宽(1358px)` → 拖 150px 只有 `0.11 × 6 = 0.7px`；
2. 松手阈值 = 内容区宽 × 32% = **435px**，鼠标慢拖/快甩都够不到 → 永远不切换。

### 方向确认（AskUserQuestion）
给三个选项（整排 tab 跟手 / 内容区真翻页 / 只滑高亮块）→ 用户选**整排 tab 跟手**。
（符合用户 work flow：方向选择给推荐项，避免第三次返工。）

### 改法
- **四条 tab 栏各加内层轨道**：药丸底色/分隔线**留外层**，跟手位移落**内层** ——
  否则底色会被一起推走（出框漏白）。栏体 `overflow` 裁剪 + 跟手态两端 12/14px 渐隐遮罩
  （整排外滑时方块是硬切在边界上的，半个字形挂着廉价）。
- `mapStripOffset(raw, limit)`：一个槽距内**严格 1:1**，越界 0.18 增益橡胶，硬顶 1.25 槽距。
- 松手阈值改 `decideSnap({ thresholdPx })` = **半个槽距**（设置页 37.5px）→「拖过一半就切」。
- `--swipe-progress` 改按**槽距**归一化（原按内容区宽）→ 边缘压暗从"最多 0.3 不透明度"变成真正可见。
- 内容层位移钳到 22px（越界硬顶 30.8 < 40px 内边距，首字不裁），主反馈交给 tab 轨道。
- 博客 `targetRef` 从「条件渲染的浮层内容体」→ **常驻轨道**（浮层收起时也看得见跟手）。
- 平均槽距（首末中心距 / (n-1)）而非逐对相邻距：逐对会因方块宽 70/82 不等，**反向拖动时限幅突跳**。

### 扩展点（向后兼容）
`useSwipeTabs` 新增 `visualMapper?: (raw)=>number`、`snapThresholdPx?: number | (()=>number)`；
`swipeTabsCore` 新增 `mapStripOffset / averageSlot / STRIP_RUBBER_GAIN / STRIP_MAX_RATIO`、
`toVisualOffset(raw, clamp?)`、`SnapDecisionInput.thresholdPx`；
新共享层 `hooks/tabStripSwipe.ts`（`measureTabCenters` / `createTabStripMotion`，四面板复用）。

### 验证
- **CDP 真机**：设置页按住方块拖 150px → 轨道 **-88.5px**（= 75 + 75×0.18，与映射公式吻合），
  内容层 -30.8px，进度 -1，松手切换 ✅；60px 小拖 → **-60px（严格 1:1）** ✅；
  反向右拖 → +88.5px ✅；四组全部切换成功。博客 → -48.5px ✅ 切换 ✅。
- 白板/知识库 tab 栏在空库时**不渲染**（白板左栏是 hover 打开的 overlay；知识库需先建库）→ 这两条靠
  jsdom 集成测试（真渲染 + 真 pointer 轨迹，量轨道位移 ≥ 30px）+ 契约测试兜住，CDP 只覆盖设置/博客。

  `swipeTabBarSurface` +20 例（CSS/JSX 两侧同断言）、`tabBarSwipeBinding` +6 例（轨道位移回归闸门）。

## 需求 N · 第四轮（R4）：选中态「搬家」为独立滑块（Apple 分段控件）

### 用户反馈（R3 被否）
> 「第一，内容区域。不要。滑动只有。功能tab栏中的功能tab进行滑动。你知不知道apple的产品？它的工具栏。是可以进行滑动的。
> 也就是说。摁住这个功能tab。就有一个显示一个方块的感觉，然后可以进行一个滑动。而且工具tab栏。也是不需要进行滚动的」

R3 是「**整排 tab 跟手**」→ 文字跟着动，**不是** Apple 分段控件。方向对了（要让位移看得见），**承载者错了**。
经 AskUserQuestion 定案（用户答「对了」）：常驻滑块压在选中项 + 按住只滑块跟手 + 文字零位移 + 内容区零位移 + 栏不滚。

### 核心认知
**这不是"给 tab 加动画"，而是"把选中态的视觉承载者搬家"** —— 激活底色/下划线从 tab 自身搬到独立的
`thumb` 元素。R3 想靠"让轨道动"解决"看不见"，R4 的解法是"让该动的东西是那条方块"。

### 实现
- 共享纯逻辑 `hooks/tabStripSwipe.ts`：`createTabStripThumb({trackRef, thumbRef, getIndex})` →
  `{ handleOffset, snapThresholdPx, place }`。`mapStripOffset` 一个槽距内严格 1:1、越界 0.18 橡胶、硬顶 1.25×槽距。
- React 壳 `hooks/useTabStripThumb.ts`（新）：组合纯逻辑 + `useSwipeTabs({ manualOffset: true })`；
  首帧/选中变化 `useLayoutEffect` 落位、`ResizeObserver` 尺寸变化瞬时落位。
- 四面板接入（手势**只挂 tab 栏**，内容区不挂）；白板用**下划线滑块**（`height:2px;bottom:0`），其余三栏圆角块。
- **滑块位置 = 基准定位 + 手势位移，合成到同一个 `transform`** —— 拆两段会有"基准跳变 + 位移清零"的视觉裂缝。
- `snapThresholdPx` = **该方向真实中心距的一半**（非平均槽距；方块宽 70/82 不等，用平均会让阈值与视觉不符）。

### 踩坑（两个，都值得记住）
1. **`transition:none` 残留**：`place(index, animated=false)` 瞬时落位后把 `style.transition='none'` 留在元素上
   → **永久压住 CSS 过渡** → 后续点击/松手落位全变瞬移（真机才暴露，jsdom 测不出）。
   修法：`apply(); void el.offsetWidth; el.style.transition = ''`。已补断言。
2. **CDP 提交按钮不能用宽正则**：`/创建|新建/` 在 `.aurora-kb-btn--primary` 上会**先命中页面底层的「新建知识库」**
   （modal 走 portal 渲染在 body 末尾，DOM 顺序在后）→ 点了无效按钮，表现为"点了没反应/没跳转"，
   极易误判成业务 bug。正解：限定 `.aurora-kb-modal .aurora-kb-btn--primary` + 精确 `/创建知识库/`。
   （附带确认：创建知识库**不会自动跳详情**，只关弹窗 + 刷新列表 → 探针需补"点卡片"这一步。）
