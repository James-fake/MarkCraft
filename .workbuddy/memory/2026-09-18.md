## 三个判断（本阶段最有价值的部分）

### ① 「禁止互相 import」是错的 → 单向
方案 3.4 原文写「app 与 panels 禁止**互相** import」。实测 `app -> panels` 11 处是装配层的**正当职责**
（AuroraShell 的职责就是组装并渲染所有面板）→ 双向禁止会直接产生 11 处误报，等于让 shell 无法渲染界面。
实现为单向：app 是 aurora 内最高位，子模块不得反向引用（app 自身 + 入口 `aurora-main.tsx` 豁免）。

### ② 守卫要开例外时，先问「能不能移动模块」（RealProviders）
RealProviders 被 AuroraShell（真实运行）+ **12 个测试文件**（render wrapper 夹具）共用。
留在 `aurora/app/` 的代价是结构性的：**守卫若想真封死 `panels→app`，就必须为 `.test.tsx` 开例外**，
而「测试夹具寄居装配层」会持续激励错误依赖（新测试照抄旧路径）。
搬到 `aurora/providers/` 后：测试边一并归零 → 守卫**零例外** → 测试文件被真实覆盖（探针 5 验证）。
**判据：当某模块的存在会迫使守卫开门时，移动模块优于给守卫留例外。**
附带好处：该文件对 `stores/`、`components/ui` 的相对深度与旧位置相同（都是二级）→ 内部 import 一行未改。

### ③ 守卫工厂加 `exempt`，避免「新增目录即盲区」复发
`_forbidden-import.cjs` 原本只支持「禁止目标」判定。要给守卫排除「app 目录自身 + 入口文件」，
若改用 `overrides.files` 列举子目录 → **每新增一个 aurora 子模块就再现一次盲区**（本仓反复踩过的坑）。
最终：作用域 `src/aurora/**` 全量 + 豁免写在规则内。并顺手把路径包含判定抽成 `inPath()`，
让 forbidden 与 exempt 两侧共用同一套语义（否则会「豁免判不中、禁止判得中」→ 不对称误报）。
**探针 3（在新建的 `aurora/navigation/` 内注入反向引用）就是这条设计的验收。**
