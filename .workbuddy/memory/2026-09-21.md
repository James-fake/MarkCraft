### 追加二：真正元凶锁定 = `git-credential-helper-selector.exe`（**归因再修正**）

用户贴出弹窗截图（标题 `CredentialHelper Selector`，选项 `<no helper>` / `manager` / `wincred`，
复选框 `Always use this from now on`）→ 一眼定性：**它在等人点按钮**。

**逐个单测三个 helper**（`<exe> get`，输入 `protocol=https host=gitee.com`）：

| helper | 耗时 | 结果 |
|---|---|---|
| `git-credential-wincred.exe` | **181ms** | ✅ 拿到密码 |
| `git-credential-manager.exe` (GCM) | **319ms** | ✅ 拿到密码 |
| **`git-credential-helper-selector.exe`** | **8s 无返回** | ❌ HANG |

⇒ ⚠️ **上一轮「转给 GCM 的 generic provider 卡住」的归因是错的**：GCM 本身完全正常。
真正卡住的只有**选择器那一层**（GUI 弹窗）。可执行文件在
`PortableGit/versions/1.2.0/mingw64/bin/`；从二进制里抠出它只用两个键：
`credential.helper` 与 `credential.helperselector.selected`。

**试错记录**：
- 用户点过 Select 后，`~/.gitconfig` 多了一条 `credential.helper = !"…git-credential-manager.exe"`
  （选择器把选择**钉**进全局）——但 selector 仍在链首，仍会弹窗。
- `git config --local credential.helper ""` **没生效**：Git **不持久化空值**，
  `.git/config` 里根本没写进去，所以清不掉继承来的 selector。
- 对照：`git -c credential.helper= credential fill` = **342ms NO_CRED**
  ⇒ 证明「命令行层空值」确实能重置整条链。

**正解（已落地，仓库级、可逆、不碰共享运行时）**：直接在 `.git/config` 手写两行 ——

```ini
[credential]
	helper = 
	helper = wincred
```

空值先重置 system/global 累积的 helper 链，再由 `wincred` 供给凭据。

### 本批新增的坑（已补进 skill `cdp-ui-interaction-verify`）
1. **读持久化先查介质**：MarkCraft 文件树写 **IndexedDB**（`fileService.saveState` → 300ms 防抖 → kv 表），
   localStorage 只有版本号。按 localStorage 读树 =「树不存在」**假阴性**（首轮探针实测踩到）。
2. **异步填充的文案不能拿「元素存在」当就绪**：详情页库名由 `loadKb(kbId)` 异步填充，
   元素先出现、文案后到 → 只等元素会采到占位「未选择知识库」（同一份代码一次过、一次挂）。**断言须轮询文本**。
3. **IIFE 式取数表达式不能直接拼 `.field`**：`waitFor(EXPR + '.found === true')` 把 Promise 当对象读 → **恒 false → 假超时**。
   要写成 `(async () => (await EXPR).found === true)()`。
4. 顺带确认：`#view=` **只携带视图名**，实体 id 在 viewState 内存里 → 「kbId 传没传到」只能用
   **详情页 subbar 显示的是库名而非占位** 来证，不能用 hash 断。
