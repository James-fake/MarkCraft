## 修「点击知识库笔记未跳编辑器，停在知识库详情页」（用户报障）

**症状**：点知识库里的笔记没有跳转编辑页，一直停在知识库详情页。

**根因（源码定论）**：知识库**详情页**里有**两份外观同款**的文件行 —— 同一类名 `.aurora-kb-recent__item`、同样的文件图标 + 文件名 + 时间：

- 「笔记」Tab（容器 `.aurora-kb-notes`）→ 有 `onClick / role / tabIndex`，**能点**；
- 进库**默认落地**的「概览 · 最近活动」（容器 `.aurora-kb-card--recent`，`KbPanel.tsx:216`）→ **纯 div**，无任何点击处理；且交互反馈（`cursor:pointer` / hover / focus）**只挂在 `.aurora-kb-notes .xxx` 上** → 它连指针都没有。

⇒ 用户看到并去点的，正是那份哑列表。
**根因本质 = 三份同款行标记被复制粘贴后各自漂移**（外观靠类名共享，交互能力靠三份手写代码各自维护）。

**修复：抽共用组件，让外观与交互「绑在一起走」**

- `kb.css`：新增 `.aurora-kb-recent__item.is-interactive` 的 cursor / 圆角 / 过渡 / hover / focus-visible；概览卡内单独 `padding: 7px 8px`（基础行 7px 4px 在卡片里贴边）。**主规则故意不写 padding** —— 避免与 `.aurora-kb-notes .xxx` 那份调优互相覆盖（同权重、靠源序决胜）；旧 notes 规则**保留**（`notesTabHeader.test.ts` 依赖该块的 padding 断言）。

### 本批新增的坑（已补进 skill `cdp-ui-interaction-verify`）
1. 🚨 **「同款类名出现在多个容器」= 起手区陷阱的变体**：`querySelectorAll(SAME_CLASS)[0]` 可能命中**另一个语义不同**的列表 → 探针全绿而用户仍在报障。修法：按**容器**限定选择器（`.containerA .row` / `.containerB .row`），逐容器断言。
2. **兜底循环的判据被前一步顺带满足 = 不诚实归因**：主机制 `element.click()` 已跳转后，真实鼠标兜底第 1 轮判据 `hash !== before` 恒真 → 报告出「真实鼠标=true」的**假证据**。修法：兜底**仅在主机制失败时**才跑，否则明确报 `n/a`。
3. **「合成鼠标点不动」的正确定性顺序**：无前台窗口时 Chromium 不派发 `Input.dispatchMouseEvent`。把可达性断言写成**条件式**（送达 ⇒ 必须跳转；不送达只记 info、不判失败），并用事件流探针（capture→native→bubble）分层证明「不是 handler 没接」，而不是直接归因成产品 bug。

### 本批新增的坑（已补进 skill `cdp-ui-interaction-verify`）
1. 🚨 **阳性对照的选择器必须「实现无关」，否则归因不诚实**：第一版探针用**修复后才存在**的 `.aurora-kb-minigraph__g` 取扫描面 ⇒ HEAD 版节点数 0、报「红」——但红的理由是**选择器在旧版不存在**，与行为差异无关（属**假阳性证据**）。改为由**修复前后都存在**的 `<circle>` 反查父节点后，HEAD 的「红」才落在真正行为上（`interactive=0/12`、点后仍 `#view=kb`）。
2. **`SVGElement` 没有 `.click()`**（Chromium 实测），`typeof el.click !== 'function'` ⇒ 派发 `new MouseEvent('click', { bubbles:true, cancelable:true, view:window })` 走 React 委托链路。
3. **Edge profile 路径必须是 Windows 形态**（`C:/Users/...`）：写成 POSIX 形态 `/c/Users/...` 会让 Edge **静默并入现有会话**（无新调试端口、日志仅「正在现有浏览器会话中打开」）→ 探针报 `CDP not ready`。
4. **`git restore --source=HEAD --worktree -- <p1> <p2>`：只要有一条 pathspec 无效，整条命令中止、什么都不恢复**（静默；`exit` 非 0 但极易漏看）⇒ 阳性对照前**必须复核「确实已回到 HEAD」**（grep 特征标记），别只看命令有没有报错。另：bash 里**禁止内联 PowerShell**（工具安全策略会拦），清理探针进程要单独用 PowerShell 工具。
