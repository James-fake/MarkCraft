### 本批新增的坑（已补进 skill `cdp-ui-interaction-verify`）
1. 🚨 **「同款类名出现在多个容器」= 起手区陷阱的变体**：`querySelectorAll(SAME_CLASS)[0]` 可能命中**另一个语义不同**的列表 → 探针全绿而用户仍在报障。修法：按**容器**限定选择器（`.containerA .row` / `.containerB .row`），逐容器断言。
2. **兜底循环的判据被前一步顺带满足 = 不诚实归因**：主机制 `element.click()` 已跳转后，真实鼠标兜底第 1 轮判据 `hash !== before` 恒真 → 报告出「真实鼠标=true」的**假证据**。修法：兜底**仅在主机制失败时**才跑，否则明确报 `n/a`。
3. **「合成鼠标点不动」的正确定性顺序**：无前台窗口时 Chromium 不派发 `Input.dispatchMouseEvent`。把可达性断言写成**条件式**（送达 ⇒ 必须跳转；不送达只记 info、不判失败），并用事件流探针（capture→native→bubble）分层证明「不是 handler 没接」，而不是直接归因成产品 bug。

### 🚨 顺带挖出并修掉一个**通用的 Store 缺陷**（`FileStore.openFile`）
现象：整跑时 `usageDocBrief` 用例 8 红，单跑绿。诊断（两次快照 + 打全 tab 表）确认：
**`openFile` 打开一个"已经在标签栏里打开"的文件时，不更新 `activeTabId`** ——
tab 的 `isActive=true` 却指着别的文件，渲染的是**错的那一篇**。
成因：旧实现把「找/建标签」与「设 activeTabId」拆成两次 `setState`，中间靠 `let newActiveTabId` 旁路传值；
而 `setState(updater)` 的 **updater 只在渲染期运行**，只有 React 的「急切求值」（该 fiber 更新队列为空）才会
同步跑一次给它赋值 ⇒ **队列非空时该变量恒为 null ⇒ 第二次 setState 被整段跳过**。
用户可见症状 =「点一个已打开的文件没切过去」（随负载偶发）。
修法：**新状态在同一个 updater 里一次算完**（含 `activeTabId`），并把「已经一致」作为 bail-out 条件。
回归锁：`src/stores/FileStore.batch.test.tsx` ③④（**同一 tick 内 A→B→A / B→A→B**，主动构造"队列非空"条件）。
