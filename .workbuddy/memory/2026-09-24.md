## 调色板定位：挂到按钮正下方 + 水平居中（高亮 / 下划线）

需求原话：「高亮颜色选择列表和下划线颜色选择列表的位置移动至相对应的按钮下方的位置，居中放置」。

### 改动
- `src/features/editor/toolbar/useDropdownPosition.ts`：给共享 hook 加**可选** `align`/`panelRef`/`gap`。
  - `align: 'center'` = 面板水平中线对齐锚点中线（= 「挂在按钮正下方」）；默认 `'left'` **逐像素保持
    历史行为**（另两个消费者 `ListDropdown` / `WysiwygHeadingDropdown` 传两参，未受影响）。
  - 水平越界夹到视口留白 8px；垂直默认贴锚点下方 gap=4，下方放不下则翻到上方。
  - `useEffect` → `useLayoutEffect`：布局副作用在**绘制前**跑完并回写 state ⇒ 不会先闪一下旧位置。
- `WysiwygToolbar.tsx`：高亮 / 下划线两处调用改传 `{ align: 'center', panelRef: <对应 menuRef> }`。
- 新增 `src/features/editor/toolbar/useDropdownPosition.test.ts`（13 例）。

### 三个实现要点（都是「不做就会错」的）
1. 🚨 **居中必须传 `panelRef`**：估算宽度 `DROPDOWN_EST_WIDTH=180` ≠ 调色板实际 226.33px
   ⇒ 拿估算值居中会**整体左偏 22.5px**。单测专门锁了这条（不传 ref ⇒ 落点 432.5 vs 正确 410）。
2. 🚨 **实测尺寸取 `getBoundingClientRect()`（分数）而不是 `offsetWidth`（取整）**：
   面板真实宽 226.33，`offsetWidth` 报 226 ⇒ 真机留下 **0.17px 固定残差**。
   换 rect 后真机 Δcx 从 0.17px → **0.00px**（rect 还能正确反映 CSS transform 缩放）。
3. 🚨 **`setPos` 必须值比较后回写**：`setPos(新对象)` 在「依赖里有 ref 对象」的 effect 里，
   若调用方传的是**每次渲染都新建的内联 ref**（`{ current: el }`），依赖每轮都变 ⇒ effect 每轮重跑
   ⇒ 自激成死循环（React 报 `Maximum update depth exceeded`）。**单测第一版就是这么红的**
   —— 值相等时回写 `prev` 让 React 跳过渲染。生产代码传稳定 `useRef` 不受影响，但护栏值得留。

### 踩坑（探针环境，属「本仓已知坑 A」的同族新变体）
- 🚨 **`cmd1 && cmd2 && EDGE ... &` 会把整条 `&&` 链丢进后台子 shell** ⇒ 前面的 `cd` 与变量赋值
  **都不在主 shell 生效**。症状极具误导性：`node .workbuddy/...` 按错误 cwd 解析、`"$LOG"` 展开成空
  ⇒ 出现**莫名其妙的退出码（实测 23）**、日志文件根本没生成、输出为零。
  正解：用 `;` 分隔，`&` 就只绑定最后那条 Edge 启动命令（`A ; B ; C &` ⇒ 只有 C 后台）。
  另注：Edge 会在该次 bash 结束时被回收，所以「启动 Edge + 跑探针」必须同一次 bash。
- 🚨 **同一次 Edge 会话里连跑两个探针，第二个会在 §0 中途静默中止**（实测日志只有 178 字节、
  却报 exit 0）—— 换**全新 Edge 实例**单跑即 37/37 全绿。⇒ **不要在同一 page target 上连跑两个探针**。
