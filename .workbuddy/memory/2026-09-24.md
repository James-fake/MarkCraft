## 调色板定位：挂到按钮正下方 + 水平居中（高亮 / 下划线）

需求原话：「高亮颜色选择列表和下划线颜色选择列表的位置移动至相对应的按钮下方的位置，居中放置」。

### 改动
- `src/features/editor/toolbar/useDropdownPosition.ts`：给共享 hook 加**可选** `align`/`panelRef`/`gap`。
  - `align: 'center'` = 面板水平中线对齐锚点中线（= 「挂在按钮正下方」）；默认 `'left'` **逐像素保持
    历史行为**（另两个消费者 `ListDropdown` / `WysiwygHeadingDropdown` 传两参，未受影响）。
  - 水平越界夹到视口留白 8px；垂直默认贴锚点下方 gap=4，下方放不下则翻到上方。
  - `useEffect` → `useLayoutEffect`：布局副作用在**绘制前**跑完并回写 state ⇒ 不会先闪一下旧位置。
- `WysiwygToolbar.tsx`：高亮 / 下划线两处调用改传 `{ align: 'center', panelRef: <对应 menuRef> }`。
- 新增 `src/features/editor/toolbar/useDropdownPosition.test.ts`（13 例）。

### 三个实现要点（都是「不做就会错」的）
1. 🚨 **居中必须传 `panelRef`**：估算宽度 `DROPDOWN_EST_WIDTH=180` ≠ 调色板实际 226.33px
   ⇒ 拿估算值居中会**整体左偏 22.5px**。单测专门锁了这条（不传 ref ⇒ 落点 432.5 vs 正确 410）。
2. 🚨 **实测尺寸取 `getBoundingClientRect()`（分数）而不是 `offsetWidth`（取整）**：
   面板真实宽 226.33，`offsetWidth` 报 226 ⇒ 真机留下 **0.17px 固定残差**。
   换 rect 后真机 Δcx 从 0.17px → **0.00px**（rect 还能正确反映 CSS transform 缩放）。
3. 🚨 **`setPos` 必须值比较后回写**：`setPos(新对象)` 在「依赖里有 ref 对象」的 effect 里，
   若调用方传的是**每次渲染都新建的内联 ref**（`{ current: el }`），依赖每轮都变 ⇒ effect 每轮重跑
   ⇒ 自激成死循环（React 报 `Maximum update depth exceeded`）。**单测第一版就是这么红的**
   —— 值相等时回写 `prev` 让 React 跳过渲染。生产代码传稳定 `useRef` 不受影响，但护栏值得留。

### 真机证据（两个探针各加一段 §3c，几何断言可证伪）
- `cdp-verify-underline-split.mjs`：**48/48，EXIT=0**；§3c `Δcx=0.00px`、`gap=4.00px`
- `cdp-verify-highlight-split.mjs`：**37/37，EXIT=0**；§3c `Δcx=0.00px`、`gap=4.00px`
- 锚点几何：下划线 wrap `{left:504.3, top:83, w:37, h:28}`；高亮 wrap `{left:602.3, top:83, w:39, h:28}`
  ⇒ 两者都取 **split 包裹层**（主按钮 + 箭头）作为锚点，符合「居中于按钮」的语义。
- 正对照依据（写进探针注释）：改动前 `left = 锚点左边缘`（左对齐）⇒ 面板中线比锚点中线**右偏 ~94px**，
  故 `Δcx ≤ 1px` 在旧版**必然红**，不是恒真式。

- 🚨 **`cmd1 && cmd2 && EDGE ... &` 会把整条 `&&` 链丢进后台子 shell** ⇒ 前面的 `cd` 与变量赋值
  **都不在主 shell 生效**。症状极具误导性：`node .workbuddy/...` 按错误 cwd 解析、`"$LOG"` 展开成空

## 思维导图模板浮层「还是最旧一版 UI」（根因：portal 逃出 aurora 作用域）

报障原话：「现在编辑功能界面……思维导图列表的样式居然还是用的是最旧一版的 ui 设计样式」。

### 定位（先证伪候选，再动手）
- 全仓 grep「思维导图」候选：`CanvasTopbar` 的「思维导图」视图（画布看板，非"列表"）、`MindmapCanvas`
  （文档内渲染）、**`features/editor/toolbar/MindmapPopover.tsx`**（内容就是「思维导图模板」列表，
  由源码模式 `MarkdownToolbar` 与 `WysiwygToolbar` 两处工具栏的「更多」菜单唤起）⇒ 用户所指即后者。
- 🚨 **真因不是"颜色写错"，而是浮层整体逃出 aurora 作用域**：该浮层 `createPortal(..., document.body)`
  是 `#aurora-root` 的**兄弟**而非子树；而 `tokens.css` 里把 base.css 旧蓝系变量重映射为 `--mc-*` 的那一层
  **只写在 `#aurora-root{}` 内**，作用域外不生效。
  ⇒ 浮层里 `var(--editor-bg/--editor-text/--editor-border/--code-bg)` 全部回落 `src/styles/base.css`
  的旧 slate（#0f172a / #e2e8f0 / #334155 / #1e293b）；`--hover-bg` 更只定义在 `.aurora-editor` 内
  ⇒ 直接落回内联旧蓝 `rgba(59,130,246,0.1)`。
  外加 Tailwind 遗留（`borderRadius: '0.5rem'`、`shadow-lg` 的 boxShadow 字面量）与魔法 `z-index: 9999`。

### 修法（回归同族基底，而非手搓一套）
- 同工具栏的兄弟浮层（`ListDropdown` / `WysiwygHeadingDropdown` / `MoreDropdown` / `SourceHeadingDropdown`）
  全都是 `className="aurora-dropdown"` —— 即「新版 UI」的正统入口（`components.css`：
  `--mc-bg-elevated` + `--mc-border-medium` + `--mc-radius-md` + `--mc-shadow-popover` + z-index 1000 + 入场动画）。
- `MindmapPopover` 改为：根加 `className="aurora-dropdown"`（内联只保留定位/尺寸）；模板行复用
  `.aurora-dropdown__item`（**删掉手写 onMouseEnter/onMouseLeave 改色**）；缩略图底改 `--mc-bg-content`
  形成内嵌芯片感；选项按钮 active 用 `--mc-accent`/`--mc-accent-soft`/`--mc-accent-text`；
  圆角 6px/4px → `--mc-radius-sm`、面板 `--mc-radius-md`、阴影 `--mc-shadow-popover`。
- 因 portal 在 `#aurora-root` 之外，内部**一律直接引用全局 `--mc-*`**（定义在 `:root`，portal 拿得到）。

### 回归锁（5 例）`src/features/editor/toolbar/portalOverlayBasis.test.ts`
核心契约：**浮层内引用的每个 CSS 变量都必须以 `--mc-` 开头** —— 任何 `--editor-*` / `--hover-bg` / `--code-bg`
在 portal 里都**必然**回落旧版值，所以它们不是"另一种写法"而是"必然变旧"（5 条断言里就数它最可泛化）。
另 4 例：根带基底类、面板外观不得内联回写、行复用 `aurora-dropdown__item`、旧版遗留字面量不得回流。
- 阳性对照：HEAD 版 **5/5 全红**，红的理由正是预言项（缺基底类、内联回写外观、
  `offending = ['--editor-text', …(5)]`、`0.5rem`）。断言前**必须剥注释**（组件正文说明里就写了 `--editor-*`，不剥会自命中）。

## 编辑器界面「旧皮肤」穷尽审计（扫描面 209 文件）

3. **自持皮肤**：Tailwind 工具类 / 内联字面量 → 与主题系统零耦合
4. **层级越界**：内联 z-index 魔数覆盖基底单源带（tokens.css §14）

  `MindmapPopover`（上轮修）、`Modal`、`aurora-filetree__ctxmenu`、`aurora-outline__ctxmenu`、
  三个 `aurora-wheel-popover`
- 🚨 **上轮修复的漏网**：`toolbar/mindmapTemplates.tsx`（`MindmapPopover` 的**子模块**）仍用
  `var(--editor-border, #475569)` / `var(--editor-text, #e2e8f0)`（L88/92）+ 硬编码老蓝
