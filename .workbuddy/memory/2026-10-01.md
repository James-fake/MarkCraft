## 剪切/复制/粘贴菜单失效检查 + 修复（commit 11366fd）

- **实锤链**（Phase C3 类型揭示问题的后续检查）：Tiptap 命令表（core/全部扩展包/项目自定义 20 处 addCommands）均无 cut/copy/paste；`createChain`（@tiptap/core dist:81-96）返回**普通对象非 Proxy**，chain.cut 为 undefined；safeCan 对不存在命令恒 false → 三项菜单 disabled 恒 true → MenuItem onClick 首行 `if (item.disabled) return` 拦截 → **WYSIWYG 下三项永久灰禁、功能空转**（callRawCommand 从不触发，无崩溃）。
- **修复**：剪切/复制 = `editor.commands.focus()` 恢复焦点（防菜单夺焦选区丢失）+ `document.execCommand`（PM 内置 copy/cut 拦截，正确序列化富文本；deprecated 但为唯一同步触发 PM 拦截的途径）；粘贴 = `navigator.clipboard.read()` 优先 text/html → insertContent 富文本，catch 回退 readText（对齐「粘贴为纯文本」既有模式）；disabled 改 `mode === 'source'`；删除 callRawCommand；safeCan 保留给真实命令（toggleBold 等）。
- 经验：**排查 Tiptap 命令是否存在，三级都查**（core 命令表 + @tiptap/extension-* + 项目 addCommands）；chain 返回值是普通对象，访问未注册命令 = undefined 调用 TypeError，且 `can()` 侧恒 false 会让「disabled: !safeCan」模式把问题转化为静默禁用而非报错——这类 bug 用户可见症状是「按钮灰了」而非异常。
- ⚠ 待人工实测：右键三菜单项实际效果；clipboard.read() 首次可能弹权限提示。
- 另一类型揭示问题（allRecords binding record 缺 fromId/props → AutoLayoutPanel 流程图布局边提取恒空）**已实锤并修复（2026-10-02 commit 716d7eb）**：实际比恒空更严重——b.props 为 undefined，场景有箭头时打开自动布局面板 edges useMemo 直接 TypeError 渲染崩溃。修复：allRecords 将箭头拆成两条 binding 半记录（fromId=箭头 id / toId=对端卡片 / props={terminal, normalizedAnchor}，id 命名对齐 getBindingsFromShape 的 bind-<id>-start/end），仅产出真实端点不伪造。新增回归锁 CanvasEngine.store.test.ts（4 例，以 AutoLayoutPanel 真实消费模式复现）。单测经验：CanvasEngine.store 的 shape rec 来自 shapesAtom（createShape 注入）、binding rec 来自 api 场景（mock attach 的 api 需含 getAppState，attach 内 serializeState 会调用）。
