# MarkCraft · 编辑器（Editor）布局范式重构 · DesignBrief

> 对应 `src/aurora/panels/editor/*` + `src/aurora/styles/panels/editor.css`。
> 范围：**整体布局范式重构**（用户拍板，2026-08-31）。非小修，是欢迎页/日记同级别的重新设计。
> 纪律基线：§18 桌面原生（bg #0D0F15 / elevated #171A21 / 发丝 border rgba(255,255,255,.08) / 唯一 accent #7C8CFF / 4-8-12 圆角 / 禁 emoji / 无玻璃无紫辉光 / 扁平非卡片化 / 信息密度高 / 键盘优先）。

---

## 1. 现状审计（重构前）

编辑器是换芯最重、结构最完整的面板，但存在两类问题：

### 1.1 布局结构问题
- **两行重工具栏**：`EditorToolbar`（返回+标题+Segmented 视图切换）+ `EditorFormatToolbar`（格式）占两行垂直高度，挤压编辑区。
- **固定两侧栏**：左 `FileTree` 240px（可折叠竖条）+ 右 `Inspector` 280px（5 文字 Tab），常驻占水平空间；进入编辑器时编辑区被夹在中间。
- **无多文档标签页**：当前编辑器一次只开一篇，缺失 VS Code/Obsidian 式的顶标签栏（文档 §8 已标"无撤销重做/多标签"）。
- **功能入口分散**：文件树/搜索/大纲/反链/脚注/写作助手/洞察/lint 各自为政，无统一召唤入口。

### 1.2 视觉纪律回退（违反 §18，须随重构一并清除）
- **玻璃效果 3 处**：`editor.css:1952 / 2116 / 2264` 的 `backdrop-filter: blur(...)` → 改实色浮层。
- **紫粉硬编码**：`#C4B5FD`(italic) / `#F472B6`(code×2) / `#34d399`(徽章绿) → 改 `--mc-*` token + 语义色。
- **emoji 工具栏**：`FloatingToolbar` 链接 `🔗` 裸 emoji → 换图标系统。
- **字号硬编码 px**：mode-btn 13 / source 14 / preview 15 等 → 统一 `--mc-font-*`。
- **幻影功能**：`.aurora-editor--zen` 禅模式 CSS 存在但未应用；`SlashCommandPopup` 的 `slashVisible` 默认 false 无触发 → 重构时决定激活或退役。

## 2. 竞品调研结论（2026-08-31 联网）

| 范式 | 代表 | 布局特征 | 适配 MarkCraft |
|---|---|---|---|
| **IDE / 活动栏** | VS Code | 最左活动栏（图标条切换视图）+ 主侧栏（文件/搜索/源码管理）+ 编辑器组（多标签/分屏）+ 底栏面板 + 状态栏；信息密度极高、键盘优先、可定制 | ✅ 最贴合用户"IDE/桌面原生/信息密度/键盘优先"偏好 |
| **知识库 / 对称侧栏** | Obsidian | 左右对称可折叠侧栏（左：文件/搜索/书签/标签；右：大纲/反链/图谱/属性）+ 编辑区多标签 + 状态栏；Ribbon 图标条在左栏顶 | ✅ 贴合知识库定位，但两侧栏常驻占空间 |
| **极简写作** | Typora / iA Writer / Bear | 所见即所得、默认隐藏侧栏、无传统工具栏（或极简）、专注/禅模式、纯写作 | ⚠️ 沉浸但牺牲知识库功能可见性，与 MarkCraft 定位有冲突 |

**判断**：MarkCraft = Markdown 编辑器 + 知识库（反链/大纲/脚注/写作助手/洞察），既不是纯 Typora 极简，也不是纯 VS Code IDE。最佳落点是 **VS Code 活动栏范式为主干 + Obsidian 的功能可见性**，兼顾信息密度与知识库能力。

## 3. 三个重构候选方案

### A. VS Code 式活动栏（推荐）
最左 48px 图标活动栏统一召唤所有面板；默认进入即纯编辑区；顶栏精简为一行（面包屑 + 视图 Segmented + 全局操作）；底栏状态栏保留。

```
┌──┬──────────────────────────────────────────────┬──────────┐
│⬡ │ 面包屑 › 文件 › 标题      [源码|所见即所得|预览]  ⌘K ···│
├──┼──────────────────────────────────────────────┤          │
│📁│                                              │ (面板,由  │
│🔍│           编辑区（进入即写）                  │  活动栏    │
│📋│           多标签页 / 分屏                     │  召唤,     │
│🔗│                                              │  默认隐藏) │
│✨│                                              │          │
│💡│                                              │          │
├──┴──────────────────────────────────────────────┴──────────┘
│ 状态栏: ●已保存  1,234 词  UTF-8     第11行 Markdown ⌘K      │
└─────────────────────────────────────────────────────────────┘
```
- 活动栏图标：文件树 / 搜索 / 大纲 / 反链 / 脚注 / 写作助手 / 洞察（⌘1–⌘7 切换）。
- 点图标从右（或左）滑出对应面板，可固定/可临时；默认隐藏，编辑区最大化。
- 顶栏一行：面包屑 + 视图 Segmented（源码/WYSIWYG/预览，分屏仍支持）+ 全局操作（⌘K 命令面板 / 分享 / ···）。
- **优**：信息密度最高、最贴合 IDE 偏好、进入即写、键盘优先、功能全可见不挤占。
- **缺**：实现量大（固定两侧栏 → 活动栏召唤的面板系统）。

### B. Obsidian 式对称侧栏 + 顶标签栏
保留左右对称可折叠侧栏，主要补「顶多文档标签栏」（当前缺失），右栏文字 Tab 改图标 Tab。

```
┌──────────┬─────────────────────────────┬──────────┐
│ [文件][搜索]│ 标签1 · 标签2 · +          │[大纲][反链]│
├──────────┼─────────────────────────────┼──────────┤
│ 文件树   │     编辑区（多标签/分屏）     │ 大纲/反链 │
│ 搜索     │                             │ /脚注/助手 │
├──────────┴─────────────────────────────┴──────────┤
│ 状态栏                                              │
└───────────────────────────────────────────────────┘
```
- **优**：改动量中等（补顶标签栏 + 右栏图标 tab）、保留知识库对称感。
- **缺**：两侧栏常驻仍占空间，信息密度不如活动栏；顶标签栏是新概念。

### C. Typora / iA Writer 式极简专注
默认隐藏所有侧栏，进入即写；格式栏改为 hover 选区浮层；加专注/禅模式（淡化非当前句）。

```
┌──────────────────────────────────────────────────┐
│ 标题（极简，hover 显示面包屑）        [WYSIWYG] ·  │
├──────────────────────────────────────────────────┤
│                                                    │
│            编辑区（进入即写，无侧栏）              │
│            格式随选区浮层出现                       │
│                                                    │
├──────────────────────────────────────────────────┤
│ 状态栏: 词数 · 已保存                              │
└──────────────────────────────────────────────────┘
```
- **优**：最沉浸、最像 Typora、进入即写极致。
- **缺**：牺牲知识库功能可见性（反链/大纲需手动拉出），与 MarkCraft 知识库定位冲突；用户偏好"信息密度"而非"极简"。
